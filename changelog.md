# Changelog

- Release 1.0.0-rc.4.1: lists, sidebars and checklists lay out correctly in the Mac app (their layout no longer depends on a stylesheet the app's content policy blocked), Home has one setup card, the theme menu shows a swatch for each skin, and the personal assistant is named Irfad’s Assistant.
- Release: the Windows installer's checksum sidecar is written in the text form ("<hash>  VyreSetup.exe"); sha256sum on Windows wrote the binary-mode "*" form, which the release's check refuses.
- Agents: a person's private assistant is named "Irfad’s Assistant" (a first name ending in s gets "James’ Assistant"). At boot, and when the person changes their display name, an assistant still wearing the default name is renamed with its folder; one the person renamed is left alone.
- Skin menu: every skin row shows a swatch (its background, a surface card and its accent), System has the half-filled circle, the open skin keeps its check, and the title-bar chip shows the open skin's swatch. The icons are inline svg with attributes only, so they draw under the desktop app's Content-Security-Policy.
- App: Home shows one setup card, the onboarding steps with icon tiles, Set up or Resume, Hide checklist and Undo, in place of the separate Get started list. ui/Row lays itself out from inline styles with a least height instead of a fixed one, so rows no longer stack on a page that drops injected style text; the Files, Records, automations and root-font stylesheets go in through the sheet too.
- Release 1.0.0-rc.4: onboarding from first launch (Personal Space first, then AI, the Assistant, a team server and members), Sign in with Google and Microsoft through the firm's own app with each person seeing only their own mail, calendar and files, memory that learns and keeps itself tidy, Ask Vyre with any agent and the screen in view, live HTTP, code and AI steps in automations, and the setup secrets locked to owners and admins. The built Mac app now starts a Personal Space, imports Claude Code and Codex sessions, creates agents and runs a sandboxed Claude Code chat turn end to end (a missing runtime file, a seal scope that overran its limit on real Space ids and a start failure that hung are fixed), and concurrent access changes can no longer write each other away.
- Moving runs onto a new version is on. A preview groups the running runs by version and step, and Apply moves only a safe group. A run moves only between steps: a step that is running is never moved or repeated, a version that lacks the run's current step is refused, and the step log is checked again just before the move. The result lists runs held back.
- Package export and import are on. An export carries the steps only: connections become numbered slots, personal AI keys are dropped, and no Vault value or run data is read. Import makes a Personal draft, puts the importer's own connections in the slots they choose, and lists what is left to connect.
- The Studio views read real data. Analytics counts runs by status, day, automation and failing step. Dependencies lists what each automation names and what is missing or off. The Live Event Explorer filters by type, shows each payload and opens the run or automation. Each has a plain empty state that says what to do next.
- Added a template gallery with four starters: a form submission to a record and a message, a weekly digest, approval before sending, and a retry-safe webhook to a record. New automation offers "New from a template", and Use template makes a Personal draft.
- Filters on All runs, Dependencies and the Event Explorer are quiet header menus with checks and counts. Every row has a click, a right-click menu and keyboard access, and Ask Vyre on an error screen now opens the assistant.
- A person removed from the Space while their run waits now has the run fail by name, and the step after the wait never runs. The access store keeps built-in role ids, so removal can unassign them, and the run message says the person is suspended or no longer a member.
- A step that sends has an "Ask before sending" setting, Off or On, in its Inspector. Off, the default, sends at once. On holds the send for approval. A Space rule that requires approval for sends still holds the send when the step is Off, and the Inspector says so. The setting is `askBeforeSending` on the step, validated to steps that send, and proved live for Off, On, unset and a Space rule.
- A Journey task "done by an Automation" now works. Entering the stage starts that Automation, and its Run succeeding marks the task done. A Run that fails or cannot start leaves the task for a person. A finished Journey task now asks the record to advance, so the stage moves on once its required tasks are done. The host's own hooks can read tasks, as they already act on every slot.
- The Automations place now mounts its config pane, run history, Failed runs, run chat with Undo, and the Journey designer, task pane and new Journey sheet with real data. The pickers list the Space's people, agents, groups, roles, channels and the Automations that use the Journey triggers. A Journey task has a "Done by" choice, and the Automations that run on leaving a stage are saved in the design.
- Install Vyre Server on a Mac with one command (`curl -fsSL https://vyre.run/install-mac.sh | sh`, attached to every release as `install-mac.sh`). Same signed release check, `--domain` and `--relay`, and folder layout as the Linux installer; a launchd agent starts it at login and another updates it daily at 04:00. It needs FileVault, Docker Desktop or OrbStack, and Homebrew's OpenSSL 3, and refuses without them. Tested on Linux and on a hosted macOS runner (the `installer-macos` job in `desktop.yml`).
- `vyre-server` and the Linux installer now run on macOS too: the encrypted-disk rule reads `diskutil` there, and the digest check falls back to `shasum`.
- feat(automations): an HTTP request step. GET and HEAD read; every other method is a send held by the Gate, recorded and not sent in a sandbox test, and carries the attempt key as its Idempotency-Key. Every request and redirect goes through the public fetcher, capped at 1 MB and 30 s. A Vault handle signs it as a bearer token, basic sign-in or named header, filled by the Vault for one call and scrubbed from the response, the log and the output.
- feat(automations): Run code is live. The code runs in the engine's bubblewrap sandbox with a network wall (no network unless the step names hosts, and a name that resolves inside is refused), 10 s of processor time, a 64 MB heap with a kernel data limit, a clean environment (no daemon variable reaches the code) and 1 MB of output. Where bwrap is missing the step is hidden, turning the automation on is refused with the reason, and the code never runs in the daemon.
- feat(automations): the AI step is live. It runs one tool-less turn through the engine's own session opener: a Personal automation on its owner's own account, a Space automation on a Space-shared key named in the step. It can run as an agent, validates an output JSON schema and fails by name on a mismatch, holds the answer for a reviewer or approver, uses a recorded sample in a sandbox test, and is counted in usage and spend caps. A repeat of the same attempt key never pays twice.
- feat(app): real forms for the three steps in the step panel, and the preview marks are gone.
- Confine a joined computer to the agent's home folder. A job token let the node call Files as the agent with all its grants, so a compromised node could read, write or delete any file the agent can reach (shared client folders). Now every home call from a node is checked on the Space (host/src/daemon/home-confine.ts) against the Files tables: whatever it names (folder, file, parent, task files) must be the agent's own Agents/<name> folder or inside it; agents.get and suggestions are only for that agent; a task is only for its owner. Unknown ids, loops and unknown calls are refused. The local Docker host path is unchanged. Tests: host/tests/home-confine.test.ts and the live door test (a shared client folder is refused for list, read, write, delete and create; the home works).
- Run agent computers on a computer that joined the Space (compute enrollment slice 3). `computers.provision` takes an optional `nodeId` (an approved computer, or a person's own for that person's agents); every call on that computer becomes a job the node answers (`computers_job`, `POST /compute/poll`, `/compute/result`, `/compute/home`). Never repeated: the node stores every job it runs and answers a redelivery from the store; a job it started and never finished is reported as interrupted, not run again; the Space keeps the first answer only; a lease that runs out twice fails the job. A job's token (one-time, hashed at rest, dead when the job ends) is the node's only door into an agent's home: that computer, the home calls only, as that agent. The node's copy of the home is a working mirror: it syncs through the existing mirror's conflict rules (Files stays the truth) and is wiped at sleep (after a sync that finished) and on removal. Live, record, stream and the Vault channel are not on a joined computer yet. Proof: modules/computers/tests/nodes.test.ts and host/tests/compute.jobs.live.test.ts (real daemon, the node in process, a stand-in for Docker).
