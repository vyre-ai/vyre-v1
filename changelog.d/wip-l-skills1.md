- Every turn's skill list now holds every skill the agent may use: Vyre's built-in ones, the Space's, and the agent's own (its library and its skills/ folder). Before, it listed only Vyre's built-ins, so a skill you added was used only if the agent went looking for it. The list tells the agent to open a skill with load_skill, which reads every tier; it used to name a tool that reads only built-ins. A long list shows the nearest 60 and says how many more there are.
- An agent that asks for its skills or loads one without naming an agent gets its own, not just the Space's and Vyre's.
- Two skills with one name are both listed now. The nearer one (the agent's own, then the Space's, then Vyre's) is used and says what it wins over; the other says which one is used instead. A Vyre system skill always wins and says so.
- A skill that cannot be read (corrupt supporting files, a SKILL.md that does not parse) is listed as broken with the reason and left out of every turn. Before, one bad row broke the whole skills list for the Space.
- A Kit never replaces a skill it did not install. Your own skill, or another Kit's, of the same name is kept, and the install says so. Undoing the Kit removes only the copy it added.
- Claude Code and Codex chats get the agent's skills as their own. Before each turn, Vyre writes the skills the agent uses (with their scripts and reference files) into the chat's work folder: `.claude/skills` for Claude Code, `.agents/skills` for Codex. Vyre's built-ins stay in the turn list, and plugin skills come with their plugin. A turn whose skills did not change writes nothing. A folder Vyre did not write, such as a repository's own skill, is never touched. In a teammate's copy of a repository the written skills stay out of what it commits. Claude Code may open them with its Skill tool in every chat mode.
- A plugin's MCP server on a Codex chat now gets its secrets and settings. Codex was told to pass the server's own variable names, but the secret was filled under Vyre's name and plain settings such as a region were dropped. The server is now started with the secret under the name it reads and its plain settings set, and Vyre's name for the secret is removed first. Codex's own key is never passed to a plugin server.
- Claude Code, Codex and Grok chats can call your connections: app hubs, OAuth servers and remote MCP servers, as API models already could. `mcp_tools` lists them, `mcp_read` calls a tool the server marks read-only, and `mcp_call` calls the rest, which waits at the Gate for an agent. All three are listed from a chat's first turn. A tool that may change things is refused as a read, and an agent can only call its own connections.
- The app hub card (Composio, Pipedream) now keeps the hub's key in a Shared folder of the Vault. It used to file it in the admin's own Mine folder, so only the admin's own calls could use the hub: a member's agent was refused. A hub connected before this keeps its key where it is; connect it again from the card to move it.
