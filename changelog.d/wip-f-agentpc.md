- When several people use one shared agent, each person who does not own it now works in a folder of their own in its computer, with their own shell history, settings and terminal sessions, so one person's files, history and open sessions are no longer there for another person's turn.
- When several people use one shared agent, each person who does not own it now browses in a browser profile of their own, so the sites another person signed in to are not signed in for them. The agent's owner keeps the agent's own browser profile with everything signed in before. What a person's turn downloads goes into that person's own Files.
- A person who does not own a shared agent can no longer name the agent's own home (its owner's settings, keys and history) or a folder of another person in a command or a working directory; the agent says so in plain words. This stops the plain way in, not a determined one: a command that builds a path inside the shell, or reads other people's running programs, still reaches what the computer's single user can reach.
- Their temporary files and the live copy of a terminal they watch now sit in their own folder, and everything of theirs on a shared agent (folder, terminal sessions, browser profile) is removed when they leave the Space (the browser profile after the Trash time, like their Assistant's).
- The browser answers one new question, which sites your own turns of an agent are signed in to (computers.browser.my_sign_ins).
- A terminal in a person's own space on a shared agent can no longer be typed into by anyone else, including an owner or admin holding its keyboard, and an agent acting for someone else cannot run commands in it.
- A person who uses a shared agent without owning it now reads, in their own terminal, that their files are in Files and that this is their own home; they cannot reach the agent's home, its project folders or the Files mirror from it, and use the Files and project tools instead.
