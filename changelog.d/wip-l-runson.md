- Where a chat runs (lane l-runson, owner rulings 2 and 3 Nov). A private chat in a Team Space runs on the place the person chose: one of their computers, one of their servers, the Space, or Automatic (the default). Automatic follows one order in one function (agent/src/placement): the computer the person is using, another awake computer of theirs, a server of their own, then the Space's server when the Space allows it (engine.space_runs, on by default). Never another member's computer or server.
- A person's Vyre app links its device daemon to each Team Space they are signed in to (POST /local/chrome/spaces from the desktop shell, compute/device-link.ts), over the Space's existing /compute/stream with their own session. The Space keeps the turn (queue, lease, tools over MCP, approvals, Stop, compaction, the record); only the engine process runs on the computer, in its own sandbox and the folders the person added from it. The Space refuses to start a process on a computer for anyone but its person, and the computer refuses too.
- A computer that sleeps mid-turn: under Automatic the chat says "Your computer went to sleep; continuing on the <Space> server" and the same turn goes on there from where it stopped (what was said and the steps done are handed to the engine there); pinned to the computer, the turn waits with "Run it on the server instead". A chat pinned to a computer that is off waits in the queue (no Working state) and starts when the computer links.
- The Runs-on options show each computer's real state (its live link), and the turn record says where each turn ran (ranOn), in order.
- A turn on a person's computer or a joined server runs in the sandbox's own work layout (<data dir>/work/<person>/<process>; it was a folder the sandbox refused), and its network rule always reaches its Space's own address (egress rule `space`), so the engine reaches Vyre's tools on a LAN or private Space.
- Approvals wake Claude Code and Codex agents, on the Space and on a person's computer: a call a CLI engine made over MCP that was held at the Gate wakes the agent when a person answers, with a note from Vyre as the next turn's input (approved and what it gave back, or declined and why; never a message in the person's name), and the chat says "Approved by <person>" or "Declined by <person>". The hold's chat, agent and person travel on gate.approved and gate.denied from hold time. A turn parked on its hold (an API engine's) still resumes as before.
