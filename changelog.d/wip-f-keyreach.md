- A key you type into an agent's request card is yours, and the agent that asked can use it. Before, when the person asked was also an owner or admin, the key was saved into the first shared Vault folder, which could be one no agent is cleared for, and the agent was refused its own key.
- A key an agent is to use is now only saved where that agent can use it. The Vault asks whether the folder (or the key you attach) is restricted above the agent, whatever the folder is called, and if so says so before anything is saved: "Choose another folder, or keep the key in your own keys." This holds for an owner, a manager answering someone else's ask, and a key attached from the Vault. A person's own folder that is not restricted is never refused for its name.
- Choosing "Anyone who asks this agent" for a key that would land in your own keys is refused in plain words, and no longer quietly becomes private. The card only offers that choice when there is a shared folder the agent can use.
- When an agent is refused a key because its folder is restricted, it now says what fixes it (move the key to your own keys or to a folder that is not restricted) and no longer asks you to share it, which never helped.
- New read call `access.clears`: whether a principal's clearance reaches what a resource is labelled.
- The names of the folders the server keeps for itself are declared once and used everywhere.
- Asking whether an agent can use a folder is open only to the server and to people who may put a key into that folder; anyone else gets "not found", the same as for a folder that does not exist.
- A manager answering someone else's key ask can no longer put the key in their own keys (the agent works for the person who asked and could not use it): it is refused in plain words, and the card says there is no folder to use instead of choosing one. A folder the server made itself (Sealed fields) is never chosen for an agent's key.
- Saving or attaching a key for an agent now refuses when the Vault cannot tell whether the agent may use the folder, instead of going ahead; nothing is stored first.
- The key request card says "Only Maya can use it through Ops" (the person's name) when that is the only way to share, instead of a one-choice list; and when there is no shared folder the agent can use, it says so and gives one button, "Make a shared folder".
- When the key card has no shared folder to offer, it says that every agent in the Space can use keys kept in a shared folder.
