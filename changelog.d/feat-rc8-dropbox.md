Dropbox as a file source. Mount a Dropbox folder, or all of Dropbox, like Google Drive or SharePoint: the folder stays the source of truth and Vyre reads its change feed, so a pass after the first reads only what changed. A person connects their own Dropbox (OAuth with PKCE, the refresh token kept in their Mine vault), or an admin connects one for the Space (kept Shared). The Dropbox app key and secret come from the Vault item #Dropbox_App, never from the code. Writes can name the revision they were based on and land only on it; a file that moved on answers a version conflict and is never overwritten. Dropbox change notices arrive at /hooks/dropbox, verified with the app secret, and its address check is answered. Dropbox is a new source in Connect a folder, with its real mark, and Connect Dropbox opens in place over the sheet.

Agents can edit mounted Google Docs, Google Sheets and Excel workbooks in place, through the provider's own API: replace text or insert text after an anchor in a Doc (refused if the Doc changed meanwhile), and read, write or append cells in a Sheet or an Excel workbook in OneDrive or SharePoint. The change lands in the real file and its version history, the file's Files grant (Edit) and the provider's own permissions both apply, and every write goes through the Gate. The Drive change feed now starts from its first pass, so a Drive mount reads only what changed.

Agents and people read PDF, Word, Excel and PowerPoint files from a mounted folder as text: files.read as text now answers the extracted text of those files instead of the bytes of a zip file. Excel cells with a date or time format read as dates (2026-10-31, not 46326), and a formula nobody has calculated reads as the formula. A PowerPoint deck reads in the order it shows its slides, with each slide's speaker notes.

A file from a connected folder opens in the app it lives in: the row menu and the viewer show Open in Google Docs, Google Sheets, Google Slides, Word, Excel, PowerPoint or Dropbox, and the press asks the provider for the file's current address, so a person who cannot open the file there gets no link. A Dropbox mount is live like the other cloud mounts: the tree and each file's revision arrive first, content is fetched when the file is opened or an agent reads it, Dropbox's history is the file's history, and a Dropbox change notice wakes the mounts on that account.

A Dropbox mount keeps syncing when nobody is signed in: the Dropbox sign-in token is a Space-only Shared Vault item, like the Google and Microsoft credentials, not a Mine item that opens only for its owner's session.
