- Agent workspaces: every agent (and so every person's Assistant) gets a small container of its own, made the first time its terminal is used, with no grant. It holds a shell, tmux, git, node 24, python and the usual tools, runs as a user that is not root with no Docker socket and no setuid program, sleeps after ten idle minutes with its files kept and wakes in about a second. The image is images/agent-workspace and is released like the agent computer image (VYRE_WORKSPACE_IMAGE in images.lock, compose.env, the server compose file and the compute-node compose).
- An agent's terminal_run, terminal_open and terminal_request now go to its workspace whichever computer its turn runs on, and the terminal tab attaches to the same tmux sessions. A person opens their own Assistant's workspace; owners and admins open a team agent's; no one opens another person's Assistant.
- Placement: an agent that has a computer is no longer pulled onto the Space server. Its turns keep own-computer-first, and its workspace and browser are reached over the Space.
- The Files folder: ~/Vyre in a workspace mirrors the agent's folder in Files (the same sync agent computers use, run as the agent), down before the first command, every few seconds while awake and once more before the workspace sleeps. A file the agent makes there shows up in Files.
- Shared project folders: each project the agent is on is one shared volume, mounted in every member agent's workspace at ~/projects/<project>. The sites runner now also judges workspace containers, their network and project volumes, and refuses anything outside that profile.
- Terminal tabs: a workspace holds many named tmux sessions. An agent opens a tab with terminal_open and a name (no host needed), runs into a named tab with terminal_run session, lists its tabs with terminal_list and closes one with terminal_close. A helper, subagent or crew member an agent starts gets its own tab in its lead's workspace, labelled "helper: <name>", sharing the lead's files and project folders; a helper lists and closes only its own tab and never reaches another workspace. Each tab says whose it is (the agent, a helper by name, or a person). Sessions that were open when a workspace slept come back empty on the next use; the list and the commands that ran stay.
- Workspaces and room: a workspace asks the host for room before it starts (1 CPU and a 1 GB cap, 64 MB held back, low CPU shares, no swap), gives it back when it sleeps or goes, and a full host queues it with "Waiting for room on the Space server. Add a compute server in Console > Computers to run more." instead of starting; it starts by itself when room opens. A computer that moves to the new model gets its workspace made, stopped, by the idle pass. The image carries the label ai.vyre.image=workspace so `vyre-server update` prunes old ones.
- Project folders in Files: the shared folder of each project an agent is on is mirrored with the project's folder in Files, through a running workspace that mounts it. A pass runs as the agent that last worked in it (a command makes that agent the one, and a pass follows a second later), so the file's history names the agent and says "edited in a workspace", and restoring a version in Files puts it back on the disk.
- Workspaces on a server that joined: when the Space has no container runtime of its own (a Personal Space on a computer without Docker, or a Team Space with none), an agent's workspace is made on a server of its owner that is connected and has Docker. The Space asks that server's Docker over the server's live socket; the server puts each question through the same policy a Team server's runner applies, so a Space that is wrong cannot make anything but a workspace there. A workspace stays on the machine its volumes are on. With no machine at all, the agent's commands go where its turn runs, as before. Room is asked for and given back on the server the workspace is on.
- The Terminal tab can ask terminal.workspace for an agent's workspace: asleep, running, waiting for room (with the line), or not made yet, where it is (the Space or a server), the projects it holds folders for, and whether this person may attach, with a sentence when not. With no machine to run it the answer is one plain line, and the agent's commands keep running where its turn runs.
- Workspaces on a server: Files and project folders of any size now mirror. A Docker request or answer larger than one frame of the server's socket travels in pieces of 2 MB (a request body is staged on the server first, an answer is fetched piece by piece), up to 300 MB in all, and an abandoned transfer is dropped after two minutes.
