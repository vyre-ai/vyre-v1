## What's new
- One Markdown editor for every Markdown body. It edits styled as you type (headings, lists, checklists, quotes, code and links), with a slim formatting bar, a small bubble on a selection, shortcuts shown in each button's tooltip, and Markdown shortcuts such as #, -, [ ], > and three backticks. A Markdown switch shows the plain text in a readable font with colour on the syntax. The bar hides in View and in Markdown mode.
- Files .md, AGENT.md, SKILL.md, the instructions of a new agent, a task's description and working notes, the body of a note, and long-text record fields all use it. The old text boxes are gone.
- What is saved is plain .md that agents read. A file you do not change comes back as it was written: blank lines, list markers, tables, HTML and front matter are kept, and text is escaped only where it would otherwise read as markup.
- Pasting strips the indent the text was copied with and turns pasted Markdown into headings and lists.
- Edits save themselves after a pause as a new version. The file header shows Saved with the version number and Undo. The Review and save row is gone; a Space that asks for a review keeps the edit as a draft with Review in the header.
- The check strip: every chip jumps to its line, and a problems chip opens the list of what to fix. The inherits check now accepts Follows VYRE.md and close variants, not only an Inherits line.
- The file header keeps Saved, the Styled and Markdown switch, View and Edit, Undo and Ask. Find, details and history moved into the ... menu.
- The highlight behind an @mention in the message box now stays on the name in a long draft. It followed the text only until the box started to scroll, then slid onto the wrong words.
- The Know page Notes field is written in the same editor; typing [[ opens the page picker at the caret.
- Version note for integration (no install was run in this lane): ui/package.json pins @tiptap/core, @tiptap/pm, @tiptap/starter-kit, @tiptap/extension-collaboration and @tiptap/extension-collaboration-cursor at 2.11.5, but package-lock.json resolves 19 packages those pull in (@tiptap/extension-blockquote, bold, bullet-list, code, code-block, document, dropcursor, gapcursor, hard-break, heading, history, horizontal-rule, italic, list-item, ordered-list, paragraph, strike, text, text-style) to 2.27.3. The editor lists its extensions itself and writes its own divider because 2.27.3 horizontal-rule imports a name 2.11.5 core does not have. To align, change the five pins in ui/package.json to 2.27.3 (or pin the 19 to 2.11.5) in one lock change; test/tiptap-versions.test.ts checks each extension against the installed core before and after.
- Chat replies draw tables (sort on a header, Copy as CSV, scroll sideways inside the message on a phone), task lists, strikethrough, links written as plain addresses, footnotes, math, callouts (> [!NOTE], [!TIP], [!WARNING]), collapsible details, images that enlarge, a safe subset of HTML, highlighted code with a language label, Copy and Wrap, charts from a small JSON block (bar, line, area, pie, scatter, with a table view and Copy CSV), and diagrams. A table or chart that is still being written stays text until it is complete, and finished blocks do not redraw.
- Every agent turn now carries a short guide to what a reply can draw and when each form fits (about 370 tokens, in the cached part of the context), and the working-in-vyre skill has examples.
- To switch on Mermaid diagrams and KaTeX math: add `mermaid` and `katex` to package.json in the same lock change, then add the one line `import "../../ui/src/stream/enable-diagrams.ts"` to the shell's startup (the file says where). Until then a diagram shows its source with a line saying it is off, and a formula shows as written.
- A file's Activity now reads in plain words for every event: "Priya Raman moved Fee agreement.pdf to Clients/Rivera", with uploads, renames, deletes, restores, shares, edits, agent reads and redactions. No ids or event names.
- A run names each step by its own title, or by what it does ("Send an email", "Wait 2 days"), never its stored id. Child runs and retries no longer print run ids.
- The composer lays its controls under the field when its own width is under 560 px (a chat column beside a task pane, a phone), so the field is never squeezed to a few words wide. The text starts at the + button's left edge, an empty field is one line, and the controls sit in a row of 32 px boxes with 8 px gaps, centred on one line. The lock now sits level with the model, effort and Send, and says in its tooltip what it does.
- The empty composer's placeholder now draws in the shared field (it never did).
- A reply that links an email thread or a calendar event with [[Name|id]] shows it as a chip; an id that does not resolve shows the Name as plain words, never the brackets. The reply guide says which ids can be linked.
- A chip for an email thread in a reply opens the Inbox conversation that holds it (new read capability inbox.thread_conversation, mapped through the stored provider thread id).
- The composer's memory switch uses the memory glyph instead of a lock: "Remembering this chat. Press to stop." and, when off, a crossed glyph with "Not remembering this chat".
- Opening an Inbox conversation from an email-thread link lands on that thread: it opens, scrolls into view and is marked for about two seconds.
- A new note (and any editor opened to type in) no longer drops the first letters: keys typed while the editor loads go into a stand-in field and are put into the editor the moment it exists.
