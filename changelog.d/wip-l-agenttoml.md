- Saving an agent's agent.toml takes the same right as changing its settings. agent.toml holds the agent's model, Vault keys, tools and limits. An outside agent, refused agents_update at the MCP door, could still change them by saving the file through Files, and the save applied. Files now asks the agents module, as the writer, before it writes a new version of agent.toml (a save, a write, a restored version, an approved changeset). The writer must be a person with Edit on the agent, or one of the Space's own agents acting for one. Anyone else is refused before anything is written, with the reason in plain words and a pointer to suggesting the change instead. agents.update, the role line and restoring a version use the same rule, so an outside agent is refused there too and not only at the door.
- The Space image can be uploaded. In Console > Space profile, Choose image… opens the file picker, and a picture can also be dropped on the section or pasted. It opens in a square crop with a zoom and a drag, beside how it will look on the rail, the sign-in page and the switcher. Save image uploads a 256 px square to Shared knowledge > Branding, a new system folder, and makes it the Space image. Choose from Files… lists every picture in the Space's folders you can see, newest first, with a search. It used to list only the Space root, which is always empty in a Team Space.
- The Space image shows wherever the Space shows its face: the rail tile, the switcher, and the sign-in, join and invite pages, where it is fetched before sign-in. It replaces the letter whenever an image is set, and a new image appears on the rail as soon as Console saves it. The Space keeps a copy of the picture (PNG, JPEG, WebP or GIF, up to 256 KB; never SVG), so the pages before sign-in can show it.
