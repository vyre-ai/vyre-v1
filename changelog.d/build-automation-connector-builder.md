- Unlimited connectors for Automations. An agent (or a person) writes a connector for any app from its API docs: hosts, how the key maps from a Vault field, actions with method, path, params and output, webhook triggers and polling triggers. `automations.connector.save` checks the definition (every problem listed at once, no key allowed anywhere) and stores it Drafted. `automations.try_read` with an app and an action sends one safe read with the key filled by the Vault, answers the level, the status and the shape of the reply (keys and types, no data) and earns Tested. A person with `connectors.manage` moves Tested to Published with `automations.connector.publish`. An agent that calls publish is held at the Gate.
- The key never reaches an agent, a prompt, a log or the definition. The definition names a Vault field, the host fills it at send time through the guarded connector port (public https hosts only, no redirect to another host), and the reply is scrubbed of the key in every spelling. The older `try_read` shape that takes a host and a Vault item from the caller is now for people only. A key goes only to a host a person allowed for that Vault item: a person names the host in their first read (`allowHost`), an agent asks with `automations.connector.trust_host` and a person approves at the Gate.
- Published actions appear in the step catalogue under the app's name, run in an Automation as `app-action` steps, and only Tested or Published ones can run in a turned-on Automation; a Space Automation can use only Published ones. Others see only what was published; drafts and tested parts stay with the author.
- Polling triggers for real: an interval, a cursor (after an id, since a time, or a page token), dedupe by item id, at most 100 items per pass, and a wait that doubles after each failure up to an hour, or the app's Retry-After on a 429. The first pass only records what exists. The host reads each due trigger as the person who owns the connector. A webhook trigger has an address with a secret that can be copied and rotated; one delivery id starts one run. New trigger `app_event`, event `app_event.received`.
- `automations.read_docs` reads a public documentation page as text through the public-fetch guard, with the links that stay on the host, so an agent can find endpoints in a docs page. The text is data, not instructions.
- The connector-builder skill ships in `agent/skills/connector-builder/SKILL.md`: how to find the API, map the key to a Vault field, write actions and triggers, test one safe read and stop at Tested. A test checks that every tool it names exists and that its example saves.
