Bring a CRM into Records. An agent fills one document, a sync spec, that says which objects the app has, where the list and the ids sit in its answers, how it pages (page numbers, a cursor, an offset or a Link header), which fields map to which record fields, which choices and pipeline stages exist, and which direction each field syncs. The spec holds the Vault handle, never the key. Vyre checks the spec against a real page of the app with read-only requests (the list, the ids, the second page, every mapped field and its type), then compiles it into a connector with its own tests, a connection, record types with fields, choices, relations and stages, and the synced-type bindings, and starts the first pull. Nothing is written to the app. Writes are compiled only where the spec cites the docs that show them, deletes stay off unless turned on per object, and a relation is read-only. The same spec applied again keeps the connector version; a changed one adds a version and only adds the fields a type lacks. 

To fill the spec from real pages, the agent has two read-only discovery helpers that use the Vault handle and can only send GET: sync_specs.sample reads one page (where the lists are, what an item holds and the types of its fields, how the next page is asked for, a total, and field-metadata or schema endpoints) and sync_specs.survey looks at up to 12 paths at once.

The sync pass now actually runs. Starting a sync schedules it in the background as the person who asked and finishes its Run with a one-line result or the reason it failed; a failure also shows in the sync log. A synced type keeps itself current by polling (one poll ahead at a time, sooner while pushes wait, ended by a pause, started again by a resume). A relation to another synced type becomes a real link to the record pulled for it and fills in as soon as that record arrives. When both sides changed a field and the newest change wins, the value that lost stays in the field's history. A record the record type refuses is skipped and logged instead of stopping the pass, and an app that ignores the page parameter no longer loops. New capabilities: connectors.sync_run and connectors.sync_poll (called by the scheduler).

New capabilities: sync_specs.validate, sync_specs.preview, sync_specs.apply, sync_specs.get, sync_specs.backfill, sync_specs.sample, sync_specs.survey (generated files need regenerating).
