Bring a CRM into Records. An agent fills one document, a sync spec, that says which objects the app has, where the list and the ids sit in its answers, how it pages (page numbers, a cursor, an offset or a Link header), which fields map to which record fields, which choices and pipeline stages exist, and which direction each field syncs. The spec holds the Vault handle, never the key. Vyre checks the spec against a real page of the app with read-only requests (the list, the ids, the second page, every mapped field and its type), then compiles it into a connector with its own tests, a connection, record types with fields, choices, relations and stages, and the synced-type bindings, and starts the first pull. Nothing is written to the app. Writes are compiled only where the spec cites the docs that show them, deletes stay off unless turned on per object, and a relation is read-only. The same spec applied again keeps the connector version; a changed one adds a version and only adds the fields a type lacks. New capabilities: sync_specs.validate, sync_specs.preview, sync_specs.apply, sync_specs.get, sync_specs.backfill (generated files need regenerating).
