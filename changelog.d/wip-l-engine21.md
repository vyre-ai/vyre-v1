- A goal's Files folder as goal/ in the work folder of a Claude Code or Codex chat that belongs to a goal (the lead's chat, or a task of the goal). modules/engine/goal-folder.ts syncs around every turn: at the start it saves anything an unfinished earlier turn left changed, then downloads the folder; at the end (before the turn's done is passed on) it uploads each changed file as a new version of the same file through files.write with the version the turn started from, and each new file, in new subfolders as needed, through files.create, all as the agent acting for the person. Nothing is deleted in Vyre from the disk, symlinks are not followed, and a file over 256 KB (the direct write limit) is left on disk and named in GOAL-SYNC.txt in the work folder.
- Conflicts keep both. A file changed in Vyre while the turn ran is not overwritten: the agent's version is saved as "<name> (agent copy)" beside it and the next turn finds Vyre's version and the copy on disk. A new file whose name is taken, also by a file the agent cannot see, becomes a copy the same way.
- The read gate holds for goal/. Every read is made as the engine, so a Not available file and a file nobody has reviewed yet (Needs review) are never written to disk, and a folder set to Not available is not entered. A file with parts hidden from AI is written with the redacted text only, read-only, and an edit of it is saved as a copy and never over the original. The rule that no disk folder with anything hidden below it is handed to an engine on a person's computer is unchanged.
- The working-on-goals skill now tells terminal agents to use goal/ (and to read GOAL-SYNC.txt first when it is there); the files tools and goals_folder stay for API chats.
- Fix: the read gate failed closed on every read of a file with parts hidden from AI, because the file.agent_read event it notes was declared on no capability, so a Redacted file could never be read by an agent through the daemon (the unit tests ran with a looser context). files.agent_view now declares it, and the gate's base64 branch no longer uses Buffer, which the module sandbox does not have.
- Rollover now has a caller. After each completed turn of a chat on Claude Code, Codex or Grok (they keep their own session), modules/engine/rollover.ts asks rolloverCheck with the input tokens the engine reported for the turn (or an estimate from the characters said since the last roll or compaction), the model's window, the turns since the last roll and whether a message is queued; at the threshold (80%, 90% whatever is queued, a queued message holds it for up to three turn boundaries, one roll per ten turns) the compactor's new roll() forgets the engine session, closes the warm process and saves Vyre's summary and latest messages for the next turn, and the chat gets one line. API engines are left to their own automatic compaction. rolloverCheck takes only the transcript's turns() and an optional chars count, so the engine module can call it without a transcript store.
- A helper's result is no longer lost when the daemon restarts in the middle of its turn. crew-watch.ts kept who the helper ran for only in memory from the turn's start, so the recovered turn (ended host_lost, no start event) posted nothing to the chat that started it. It reads the person from the turn's record now, and the chat hears "Helper ... was stopped when the server restarted. It may have done part of its work" instead of a result it did not give.
- The chat's "After this: it goes in when this turn ends" line is on the screen. The model had it, but Conversation.tsx drew the queue row with queueNote called without ownTurn, so while someone else's turn ran, your waiting message read "1 message queued for Intake's next step" and the After this wording never appeared. apps/app/src/places/chats/conversation/after-this.test.tsx draws the real Conversation for both cases, and scripts/shots/mounts/AFTERTHIS_01.tsx is the screenshot mount. The queue row wraps on a phone, so the note stays whole and Stop and send drops under it.
