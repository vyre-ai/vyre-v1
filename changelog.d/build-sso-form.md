- Console > Policies > Sign-in has "Sign in with Google" and "Sign in with Microsoft" forms: Client ID, Client secret (kept in the Vault as a Space-only item, only its handle is saved, never shown again), the firm domain, and for Microsoft the Tenant ID (a GUID, never common or a domain name). Each shows the redirect URL to register with a Copy button, On or Off, Save and Test it. The onboarding card "Sign in for your domain" has a Set up button that opens this page.
- The SSO client secret is filed in a Restricted Vault folder and item, so only Owner and Admin can list, read, use or change it: a Member, a Developer, a Guest and every agent are above their clearance. A live test on a booted daemon proves it.
- All the setup secrets are filed the same way: the GitHub sign-in client secret, the Google Workspace service-account key (Google_DWD) and the Microsoft 365 app secret (Microsoft_App) now go into a Restricted folder as Restricted items, so a Member and every agent can neither list, use, read the history of nor overwrite them. The two setup pages use their own dedicated "Company connections" folder (never an unrelated one). The server still reads them as itself for setup, probe and mail sync.
