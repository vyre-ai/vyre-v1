- The golden job is split into two shards (golden-1 and golden-2), each with its own 5 minute cap; the required golden check passes only when both shards pass. The hourly main run does the same.
- A release version bump no longer misses the CI dependency cache: the project's own version is left out of the cache key.
- The release publish step can be run again after a cut run: files already on the release with the right size and checksum are skipped, half-written ones are replaced, big files upload side by side, and the channel manifest (beta.json) is always uploaded last.
- The seed speed test (schema seed.perf) holds its 200 ms budget to the median of five rounds after a warm-up round, so one slow disk flush on a shared host no longer fails it.
- Two daemons in one process: when a second engine host half is wired over the first, the first one's opener (CLI sessions, MCP socket, egress proxy) is now closed, and its host half is told to wait for it.
- portal.live test: seven daemon boots became three (one shared by the tests that can share, one for the rate limit test, one for the landing page test); the file runs in 15 s instead of 29 s on the same host.
- The nightly perf file perf/server/server.test.ts is split into three files (load, write, sockets) with a shared support module, each its own perf entry in test/slow.json with the same 120 s cap and the same assertions. They share the seed template cache of the host instead of each building the full 100k contact Space.
- The connection_count probe opened its socket with the session token in the address, which the Space no longer accepts; it now asks for a one-use ticket first. It was failing behind the watchdog.
- The golden shards deal out the long step tests (joining, offline conflict, senders, key failure, matrix, purge) across both shards; the first split put all of them in shard 2 (3m29s against 30 s for shard 1).
- The generator now writes the compiled validators one file per module (generated/validators/<module>.ts, with the shared schemas in generated/validators/core.ts and a schema used by one module compiled into that module). generated/validators.ts stays as the index that merges them, so every existing import works. The chats sample imports only the four modules it checks: the two chats provider test files take about 7.2 s cold instead of 8.5 to 8.9 s.
- Two daemons in one process (tests): when the daemon that wired a module seam last stops, the daemon wired before it that is still running gets its own seam back. Before, it was left with nothing, and records.create answered "no type" for a type schema.apply had just made. Tests: a daemon that has served work keeps its record store after a second one boots and stops; the seam hand-back.
- portal.live now shares one daemon for all but the rate limit test (10.8 s for the file, 29 s at the start).
- The golden job now runs in three shards (golden-1, golden-2, golden-3 under the required golden check): with two, shard 2 still took 3m46 against 62 s for shard 1 in CI.
- The four data modules (records, schema, sources, connectors) now keep one handle per Space store and serve each call from the store whose daemon the call's ctx.db belongs to (perSpaceStore in host/src/daemon/store.ts). Two daemons running at once in one process no longer share or swap stores. Test: two daemons at once, each with its own types and records, and the first still works for records, schema, sources and connectors after the second stops.
- The two Chats tests that checked the contract through generated/validators.ts now use the per-module validator files (apps/app/tests/validators.support.ts); no app test imports the index any more. Cold: chats-mounted 9.7 to 8.4 s, chats-sidebar 4.5 to 3.7 s.
- The golden harness fails one flow, naming it, when its steps do not finish in 60 s (GOLDEN_FLOW_CAP_MS), and its test bounds the CLI run at 100 s, instead of a stalled flow holding the whole file until the 120 s watchdog. GOLDEN_TIMES=1 prints each flow's time.
