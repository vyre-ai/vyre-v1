Setting up a firm's Space through the API no longer needs workarounds. A relation made inside a type's own create call now gets both ends, as relation.add does (the other type gets the other field, named by the relation's inverse or by the type). records.bulk_upsert, records.create and records.update take a plain value for a sealed field and seal it into the Vault on write, so an import no longer loads values as text and retypes them. Sealing several fields of one type in a single schema call works (each row takes all its references in one write). A retype can name a label in its def and keeps the field's label otherwise; a label changed through schema.apply no longer fails the whole call. The Vault items behind sealed record values, and their Sealed fields folder, are out of the Vault list, search and folder list a person sees, in every Space including ones that already had them; they open only through the field. A claim page opened through an SSH tunnel at http://localhost can now carry an existing Vyre account from another Space: that Space's carry door answers a page on loopback over http as well as another Space's https page.
