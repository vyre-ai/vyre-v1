- CI runners (backend, no screens yet): the new `ci` module runs a Space's GitHub Actions jobs on throwaway cloud machines that the Space pays for with its own DigitalOcean key from the Vault. One machine runs one job through a just-in-time runner and is deleted afterwards; a sweeper every 2 minutes deletes any `vyre-ci` machine that is past the job limit plus 10 minutes or has no live run. Capabilities: `ci.settings.get` and `set` (admin, audited), `ci.runs.list` and `get`, `ci.cost.month`, `ci.project.get`. Events: `ci.run_started`, `finished`, `failed`, `swept`, `ci.job_refused`, `ci.paused`.
- CI runners: a job starts only when its labels include the Space's labels and its repository is linked to a project; at the concurrency limit it waits, at the monthly cap it is refused and the admins get an Inbox line. A fork pull request never gets a machine while the repository holds secrets (or when that cannot be told). Cost is per second with the provider's 60 second and one cent floor, rounded up.
- GitHub: `workflow_job` deliveries become `workflow_job.queued` and `workflow_job.completed`; new capabilities `github.runners.jit_config`, `github.runners.remove` and `github.actions.secrets`. The App now asks for Actions read, Administration write and Secrets read; an App made earlier must accept them.
- CI runners: each run is linked to its project's Linked tab (`projects.links.link`, kind `ci.run`, state Running, Passed or Failed, a label with the job and the minutes, the job address).
- GitHub, one connection per person: `github.me.connect`, `complete`, `status`, `disconnect` (user-to-server OAuth with PKCE through the Space's own GitHub app when an admin set one up, else the default Vyre app; the refresh token is kept in the person's own Vault and rotated on every refresh), `github.me.reach` (repositories and organisations with install state and the install or request address), `github.me.policy.get` and `set` (read, push a branch, open a pull request, comment, merge, push to the default branch: Always, Ask me first through the Gate, or Never) and `github.me.usage` (the Used by list).
- GitHub: `github.token` is the one token broker. It hands out a short-lived installation token narrowed to one repository and to what the kind of use needs, as a filler handle and never the token, only after the person's own token shows they reach the repository. An agent gets it only on the person's own turn. `github.session_env` gives a Claude Code, Codex or Grok turn GH_TOKEN and a git credential helper for the repositories the person lets run without asking. No personal access token is stored anywhere.
- GitHub, one flow: connecting and signing in are one thing. `github.me.complete` also links the GitHub to the sign-in, with a one-use ticket only the server can mint, and a sign-in with GitHub connects it too when the app issues expiring tokens. The callback is `GET /hooks/github/connect` (code and state go back to the app in the address fragment, only to this Space or a loopback address; the state is single use and the PKCE verifier stays on the server). The Space's own GitHub app is used when it has one, else the default Vyre app from the server's `VYRE_GH_OAUTH_CLIENT_ID` and `VYRE_GH_OAUTH_CLIENT_SECRET`; with neither, connecting says so plainly.
- Vault: two host-only calls, `vault.mine_set` and `vault.mine_remove`, keep GitHub's rotated refresh token in the person's own Mine item "GitHub" (sealed under their key like any Mine item), so a refresh on an agent's turn is saved too.
- Engine: a Claude Code, Codex or Grok process started for a chat of a project whose Files folder points at GitHub gets GH_TOKEN, GITHUB_TOKEN and a git credential helper (git's own GIT_CONFIG_* variables) from the broker, for that process only and for what the person lets run without asking.
- GitHub: `github.pull_request.get` takes an optional `consumer`, follows the person's read policy and shows in Used by.
- CI security: the runner download is checked against the checksum GitHub lists for that release before any machine starts (a mismatch, a missing checksum or an unreachable GitHub refuses with a plain note and one Needs-you line a day, `ci.blocked`); the machine checks the file against the same pin again before it runs it.
- CI: a project with no git remote in Files still gets CI from its Linked tab (a repository rule, or a linked pull request or commit). `ci.project.get` says when the GitHub App needs new permissions (`appNeedsAccept`, `acceptUrl`).
- Engine: the GitHub token a session holds is removed from everything its process writes (stdout and stderr, so texts, tool details, errors, step lines and logs), for Claude Code, Codex and Grok, until the token ends.
