- CI runners (backend, no screens yet): the new `ci` module runs a Space's GitHub Actions jobs on throwaway cloud machines that the Space pays for with its own DigitalOcean key from the Vault. One machine runs one job through a just-in-time runner and is deleted afterwards; a sweeper every 2 minutes deletes any `vyre-ci` machine that is past the job limit plus 10 minutes or has no live run. Capabilities: `ci.settings.get` and `set` (admin, audited), `ci.runs.list` and `get`, `ci.cost.month`, `ci.project.get`. Events: `ci.run.started`, `finished`, `failed`, `swept`, `ci.job.refused`, `ci.paused`.
- CI runners: a job starts only when its labels include the Space's labels and its repository is linked to a project; at the concurrency limit it waits, at the monthly cap it is refused and the admins get an Inbox line. A fork pull request never gets a machine while the repository holds secrets (or when that cannot be told). Cost is per second with the provider's 60 second and one cent floor, rounded up.
- GitHub: `workflow_job` deliveries become `workflow_job.queued` and `workflow_job.completed`; new capabilities `github.runners.jit_config`, `github.runners.remove` and `github.actions.secrets`. The App now asks for Actions read, Administration write and Secrets read; an App made earlier must accept them.
