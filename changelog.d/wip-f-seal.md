- Saved browser sign-ins are now locked on the server while nobody is using them. An agent computer's browser profile (cookies, saved logins, history) is encrypted and taken off the Docker volume when the computer sleeps, and put back when it wakes. Each agent's browser in the Space browser is locked the same way when its browser goes idle, and unlocked by its next step. A copy of the volume or of Docker's own data holds nothing readable.
- If the server stops, or a computer's container dies, while a profile is unlocked, it is locked again at the next start or within a minute. A locked profile that was changed, cut short or cannot be opened is never started over: the computer says so and the locked data is left as it was. A wake or a restore that fails halfway never replaces the good locked copy. Profiles from before this update keep their sign-ins and are locked at the first start or sleep.
- A saved browser profile over 1 GB is left unlocked rather than half locked, and shows as a warning in the computers health. Locking and unlocking stream, so a large profile no longer fills the server's memory.
- A missing seal key now refuses to wake a computer instead of making a new key, and a Space browser profile that is locked cannot be started by a viewer or a take-over until it is unlocked.
