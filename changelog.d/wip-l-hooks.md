- Hooks: one hooks layer for every model, the `hooks` module (`hooks.list`, `set`, `remove`, `pause`, `runs.list`, `policy.get`, `policy.set`, and `hooks.fire`, which the engine, the tool session and the CLI shim ask). A hook runs at session.start, prompt.submit, tool.before, tool.after, outward.before, turn.end, helper.start or helper.end, as a command (in the agent's sandbox, exit 2 stops it), a check (a small model reads one instruction on the asker's own AI account and answers allow, block with a reason, or a note) or one action (through the normal Gate).
- Hooks: scopes run Space, person, agent, chat, run in that order, and an admin's block ends the run of hooks. An agent sets hooks for itself, for a chat it is in and for its own run and the helpers it starts (agent tools `hooks_list`, `hooks_set`, `hooks_remove`); a helper inherits the run's hooks and can be given extra ones. An agent can only add checks, notes and its own actions: never Space or person hooks, never a change to a hook it did not make, never an action that approves, grants or changes hooks, settings or access. A Space admin can turn agent-made hooks off for the Space.
- Hooks: a hook that errors or runs out of time never blocks; it is logged (`hooks.runs.list`) and a quiet line says so once. Reasons and notes are cut of anything shaped like a key. Adding, changing, removing or pausing a hook, and a block, leave a quiet line in the chat (`chat.hook_line`, block `hook`).
- Hooks for all models: Vyre's own tools fire tool.before, outward.before and tool.after for every engine (the MCP session of a CLI engine had no hooks before, so plugin hooks never ran there; plugin hooks are now one source in the layer). The turn engine fires session.start, prompt.submit, turn.end and, for helpers, helper.start and helper.end for every driver. Claude Code gets a generated `--settings` hooks config, Grok and Codex a generated hooks file, each running the vyre-hook mode of the bridge shim, so the CLI's own built-in tools and subagents are covered too. Codex trust hashes are written; the Grok and Codex files are not yet proven on a real account.
- Hooks, the chat and the pane: a hook card says when it last ran in plain words ("Last ran 2 min ago, stopped sending an email"; no tool or capability name reaches a hooks screen, and one in a hook's own words is swapped for what it does); the Edit form uses quiet pickers (When, Only for, What it does), never pills; a stop line offers the steps a check wrote (up to two, plain words, no links or tool names, pressing one says it to the assistant as your own message) beside Details, Run once anyway and Ask an admin (`hooks.allow_once`, `hooks.ask_admin`). Every hooks call checks who is calling through lib/trust.ts: a tenant's service is refused everywhere; the engine and host only fire for a named person and read.
