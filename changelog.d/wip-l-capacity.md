- Agent computers: a host now checks room before it wakes one. Memory, disk and `machines.maxAgentComputers` (half the cores, at least one, unless an admin set it) are enforced. A full host queues the wake with a line on the computer ("Waiting for room on the Space server. Add a compute server in Console > Computers to run more.") and starts it by itself when another computer sleeps, is removed, or room opens. Making a computer on a full disk is refused with the way out.
- The room check is one shared set of calls (`claimRoom`, `releaseRoom`, `bindStarter`, `drainWaiting` in `modules/computers/capacity.ts`) for desktop computers, workspaces and Space browser profiles. Workspaces default to 1 CPU and 1 GB, burstable; desktops keep today's 2 CPUs and 4 GB.
- `vyre-server update` now removes agent computer, workspace and Space browser images that no kept release names and no container was made from, after a healthy update. Hand-tagged images and anything Docker says is in use stay. (MLA had 16.6 GB of old agent computer images.) Workspace and browser images should carry the label `ai.vyre.image`, so an untagged copy is recognised.
- An existing agent computer (Dex on MLA) moves once to a workspace and a Space browser profile that keeps its Chrome logins: Chrome's user-data is read from the sleeping computer and imported into the profile. It runs in the first idle pass after the update, only for computers that are asleep, tries a failed step three times, and leaves the old computer asleep (nothing is removed). The workspace and browser calls are bound by the workspace and Space browser work; until both exist nothing runs.
