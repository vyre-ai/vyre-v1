- Agent computers: a host now checks room before it wakes one. Memory, disk and `machines.maxAgentComputers` (half the cores, at least one, unless an admin set it) are enforced. A full host queues the wake with a line on the computer ("Waiting for room on the Space server. Add a compute server in Console > Computers to run more.") and starts it by itself when another computer sleeps, is removed, or room opens. Making a computer on a full disk is refused with the way out.
- The room check is one shared set of calls (`claimRoom`, `releaseRoom`, `bindStarter`, `drainWaiting` in `modules/computers/capacity.ts`) for desktop computers, workspaces and Space browser profiles. Workspaces default to 1 CPU and 1 GB, burstable; desktops keep today's 2 CPUs and 4 GB.
- `vyre-server update` now removes agent computer, workspace and Space browser images that no kept release names and no container was made from, after a healthy update. Hand-tagged images and anything Docker says is in use stay. (MLA had 16.6 GB of old agent computer images.) Workspace and browser images should carry the label `ai.vyre.image`, so an untagged copy is recognised.
- An existing agent computer (Dex on MLA) moves once to a workspace and a Space browser profile that keeps its Chrome logins: Chrome's user-data is read from the sleeping computer and imported into the profile. It runs in the first idle pass after the update, only for computers that are asleep, tries a failed step three times, and leaves the old computer asleep (nothing is removed). The workspace and browser calls are bound by the workspace and Space browser work; until both exist nothing runs.
- Right pane > Computer is now two sections, Terminal (the agent's workspace: state, tmux sessions, shared project folders, Attach for people who may) and Browser (its profile in the Space browser: live view, Take over or Give back, the logins it keeps). Nothing to set up. People who may not attach or take over see the state and why, not the sessions or logins. A full host shows the plain waiting line in both. The new layout draws once the workspace and Space browser data are bound (`workspace` and `browser` on the pane data); a pane with neither keeps the single-computer tab.
- machines.rooms now also returns `maxAgentComputers` per machine (what an admin set, else half the cores). The computers module reads it before it wakes a computer, so a limit an admin set applies when a member or an agent wakes one.
- machines.maxAgentComputers now counts full desktops only. A browser profile holds back 256 MB and a workspace 64 MB of a host's memory, so every agent can have both on a small server. Terminal sessions name their owner (the agent, "helper: Tess", or a person), the agent's own first. When the workspace and the browser wait for the same reason, the line is said once at the top.
- The Computer tab's Terminal section is wired in the shell: the agent's workspace is read from its terminal sessions (whose tab each is), Attach opens the agent's own session in the Terminal tab (opening one first wakes the workspace), and Attach is offered for your own Assistant and agents, and to owners and admins for the Space's agents. The Browser half stays behind its interface until the Space browser lands.
- An agent that still has a desktop computer keeps today's Computer tab until the Space browser is bound for it; agents without one use the Terminal and Browser layout now.
- The Browser section is wired in the shell to the Space browser: its state and who has the controls from computers.browser.profiles, Take over and Give back, and the live view (watching is MJPEG; after a take over it reopens on the WebSocket, which carries the frames and your clicks, wheel and keys). An agent that still has a desktop computer now gets the Terminal and Browser layout.
- The Browser section now shows a browser waiting for room with the server's line, lists the logins its profile holds (computers.browser.sessions, only while it runs, for people who may take it over), and signs out of a site (computers.browser.sign_out).
- The browser live view scales your clicks from the frame size the stream reports, or the picture's own size, and accounts for bars around the picture; no fixed page size.
- The Terminal section reads the workspace's state, its waiting line, where it runs and who may attach from terminal.workspace (one source for the attach rule); sessions still come from the agent's terminal rows, and project folders show by name.
