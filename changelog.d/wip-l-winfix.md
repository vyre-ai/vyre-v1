- Windows: folders you add from a Windows PC now reach your AI engines. Vyre accepts drive letters (C:\Users\Dana\Client Files), network shares (\\nas\legal) and long paths, spaces included. It still refuses a drive's root, the Windows, Program Files and ProgramData folders, and Vyre's own data folder, whatever the letter case or slash.
- Windows: Vyre now knows where Windows keeps your keys and saved sign-ins (Credential Manager, DPAPI and private-key folders, Chrome, Edge and Brave profiles, Firefox profiles, 1Password, your .ssh keys), so the sandbox can keep engines out of them even inside a folder you added. git over SSH uses Windows OpenSSH and its agent's named pipe, so your keys stay with the agent.
- git over SSH works when a path has a space in it, such as a Mac's "Application Support" or C:\Users\Dana Reyes.
- Codex: plugin servers that need a secret now start on Windows. Vyre starts them through a small Node launcher instead of /bin/sh, and npx and other .cmd programs are found and quoted the way cmd.exe expects.
- Skills: one file Windows refuses no longer drops all your skills from a Claude Code or Codex chat. Vyre renames files with characters Windows can't hold (: * ? < > |), trailing dots and spaces, or device names (CON, NUL, COM1) and writes deep paths in Windows' long form. A file named skill.md never replaces a skill's SKILL.md.
- Models: listing an engine's models closes it gently. Vyre ends its input and waits for it to exit, so Codex finishes saving its model list on Windows. Vyre force-closes the engine only if it has not exited after a few seconds.
