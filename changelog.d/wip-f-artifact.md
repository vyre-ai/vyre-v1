- A Space whose address is a vyre.run name that points straight at its own server (not through Vyre's relay) now opens artifact pages at its own address (a.<address>), served by the server itself. Before, the server guessed from the name ending that it was reached through the relay, handed out an artifact address nothing answered, and an artifact opened as a blank white page.
- The server checks that its artifact address really reaches it, when it starts and again every minute. Until it does, an artifact says so plainly instead of opening a page that cannot load, and Console, Health shows one line with the DNS record to add; once the record answers, artifacts open with no restart.
- An artifact tab now checks that the artifact address answers before it shows the page. If it does not, the tab shows "This page could not be loaded from the Space" with Retry and what is wrong, never a blank white area.
- A web request trigger, public links and a site's address on a vyre.run name that points straight at its server are now the server's own, not the relay's: they no longer wait on a relay check, and the "sandbox with no cookies" note on a site no longer shows for it.
- The Chrome extension recognises an artifact tab of a Space on a direct vyre.run name, so its picture is taken as for any other Space.
- A server address set by hand for artifact pages (VYRE_ARTIFACT_HOST) now gets its web server route and certificate like the Space's own address.
