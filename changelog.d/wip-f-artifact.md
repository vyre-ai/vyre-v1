- A Space whose address is a vyre.run name that points straight at its own server (not through Vyre's relay) now opens artifact pages at its own address (a.<address>), served by the server itself. Before, the server guessed from the name ending that it was reached through the relay, handed out an artifact address nothing answered, and an artifact opened as a blank white page.
- The server checks that its artifact address really reaches it, when it starts and again every minute. Until it does, an artifact says so plainly instead of opening a page that cannot load, and Console, Health shows one line with the DNS record to add; once the record answers, artifacts open with no restart.
- An artifact tab now checks that the artifact address answers before it shows the page. If it does not, the tab shows "This page could not be loaded from the Space" with Retry and what is wrong, instead of a blank white area. The check runs only against a server of this release or later (it says it checked its own artifact address); an older server's artifact pages open as they did before.
- A web request trigger, public links and a site's address on a vyre.run name that points straight at its server are now the server's own, not the relay's: they no longer wait on a relay check, and the "sandbox with no cookies" note on a site no longer shows for it.
- The Chrome extension recognises an artifact tab of a Space on a direct vyre.run name, so its picture is taken as for any other Space.
- A server address set by hand for artifact pages (VYRE_ARTIFACT_HOST) now gets its web server route and certificate like the Space's own address.
- In the desktop app, pressing Share (or opening a menu) on an artifact no longer ends with "This link has ended": the page comes back at a fresh one-time address instead of replaying the spent one. The line under the artifact's name is read again after sharing, so it shows who it is shared with.
- A one-time link that has been used, shown inside Vyre (in the web app and in the desktop app), no longer offers "Open Vyre" (which opened the app inside itself).
- `vyre-server doctor` checks that the Space's artifact address resolves to this server and answers as this Space, and names the DNS record to add when it does not. `VYRE_ARTIFACT_HOST` can now be set from the server's settings file.
- An agent's browser step whose saved picture cannot be drawn now says "No picture of this step could be taken" instead of showing a blank box.
- In the desktop app, an open artifact keeps its place and state while the Share sheet or the "..." menu is open: the page steps aside and comes back as it was, with no flash and no reload. It only reloads (at a fresh address) if the app no longer has the page.
- Sharing an artifact, file or folder now says what happened in the top bar ("Shared with Ada", or that it did not go through). Sharing with an agent, such as the Assistant, no longer fails because of an empty level.
- An agent computer's live screen asks for a new stream ticket when its picture stream fails, instead of reusing one that is spent.
- Copy link in the Share sheet (and every other Copy link: notes, files, chats, messages, agents, records) now copies the Space's own address. In the desktop app it copied an address that begins tauri://localhost, which opens nowhere. A Space with no public address says so in words instead of copying a dead link. An address under /a/ that is not an artifact's now answers a plain page, not a raw error.
- The artifact card in a chat and a record's Copy link also copy the Space's own address, not the address of the page the app runs in.
- On a Space with no public address, Copy link in the desktop app copies a link that opens in Vyre on this computer only and says so; a link for other people (the Share sheet) says there is none. In a web page at a local or network address it copies that address, which opens for that person.
