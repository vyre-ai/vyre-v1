- Making a project from a chat no longer fails on the Manage grant. The person who makes a project, and their own assistant acting for them, hold Manage on it; the Space owner's assistant can add teammates and give an agent a computer for them.
- A project that fails half way is removed, so no second "Crew test" is left behind and Projects only lists a project that Open can open.
- The people a new project starts with now get their role on it (the host step that writes them was being refused).
- A crew now starts on the person's own computer with nothing to set up: when a project has no repository, "start a crew" makes a local git repository in the project's folder (main as its start), teammates work on their own branches there, and Merge lands them. GitHub stays optional, for push and pull requests.
- A chat running on the person's own computer no longer hears "there is no computer". It hears that Vyre has no terminal open there yet and that the assistant's own shell in its work folder is the way to run commands.
- /usage now tells the truth about a Claude Code chat. A turn records the model its engine really ran on instead of "unknown", and usage shows the cached input apart from the fresh input (a turn of many requests re-sends the whole chat with each one, and the totals added all of them). The chat's size is what the last request carried.
- Usage can be grouped by the account that paid, and the usage for a chat names the model and account of its latest turn and who paid, so it agrees with the turn's own details.
- The line "Ran on a team model; Claude isn't on the team key" is now said when the turn really opens on that model, never for an account that was only considered. The turn's record names the model that ran.
- An assistant can read its chat's usage and limits. It was refused with "no valid session" because it asked where the person's computers are as itself instead of as the person it acts for.
- Crews work in any chat. "Start a crew of two" in a plain chat makes the chat's own work folder and a local git repository on this computer, starts two teammates that belong to the chat (not the Agents page) on their own branches, and Merge lands them. In a project chat they use the project's repository. Nothing has to be set up first.
- A new project's chat starts with its lead (the project's lead teammate, or else its maker's Assistant), so a plain message in it is answered.
- Only a person's own Assistant acts as the owner on a project it made and on the Space. Another Space agent asked by the same person does not, and handing out access, moving the Space's ownership, ending the Space and removing people stay with a person.
- Someone who can see a project but lacks Manage is told "You need Manage on this project" instead of "that project does not exist".
- Agents can hand work to each other with an @mention: at most three hand-offs follow one person's message, the same two agents pass it back and forth at most twice, the chat shows "Intake asked Docs", and each agent's context lists who is in the chat and what to use them for.
- A person named in a message who is not in the chat is a reference, not an address: the lead answers. The composer says "Goes to Aliza; no agent will reply. Ask Dex too" when the person named is in the chat.
- In group chats, discussions and channels agents keep replies very short and conversational, like a person in Slack. A 1:1 chat keeps the agent's own style.
- An agent shared with the Space messages a teammate as itself, with its own name, in its own chat with them. They reply there and the agent answers there, and the chat it was asked in gets one short line. The person who asked cannot read that chat unless the teammate adds them. A person's own Assistant keeps writing in their direct chat as "<Person> (Agent)". people_status tells the agent which way applies and shows people by name and a short handle, never by id, and an id that slips into a reply shows as the person's name.
- A crew in a chat with no project reads its repository with engine.crew.chat_repo.
- Where the only people present are the person and agents acting for them (a task thread on their task, a note thread, a goal chat, their 1:1), their one agent answers without an @. An @ is only needed to pick among several agents, or when other people are present.
- A turn that was stopped says why in plain words (a new message came in, Stop was pressed, a limit, the person left, the task moved, the server went away) instead of a bare "Stopped."
- Helpers are one row each, updated in place: the helper's name and status ("Working · 13s", then "Done"), one line of what it found, and Open. The helper's report no longer shows as a second card, and the parent no longer pastes helper replies: the guidance tells it to give one short answer in its own words. Hovering a helper link now uses the same access check as clicking it. A helper chat shows its brief as a block under "Helper chat · started by <agent> in <chat>", with a link back to the message. Helpers get task_submit and task_ask listed from the start, and every agent is told never to name tools or ids to people.
- Helpers can be watched and steered. engine.helpers.status gives each helper's state (working, done, needs you, failed, stopped), the step it is on in plain words, one line of what it found, its time and its cost; the person it works for can ask a running helper something (chat.helper.steer); Stop all stops every helper under a chat.
- Helpers run on the right model, and the agent chooses it. models_for_helpers lists every AI account the person may use with its models, tiers (cheap, standard, strong) and availability. A helper can be started on a named account and model; by default it stays in the parent's provider and takes a cheap model to read and a strong one to reason. An account the person may not use is refused, an unavailable model falls back inside its account and the helper says which one it used, and each agent has a "Helper models" setting (same provider, any provider when I ask, or always ask first).
