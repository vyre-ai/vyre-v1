- AI sign-in is direct again. Onboarding's Connect your AI and Settings > AI accounts have "Sign in with Claude", "Sign in with ChatGPT" and "Sign in with Grok". Pressing one asks the server to start that provider's own sign-in (`providers.subscription_start` now answers the link, the code to type where the provider shows one, and whether a code is pasted back). The browser opens; the person approves; Claude shows a code that is pasted into a field, ChatGPT and Grok show a code to type there and the page finishes by itself (`providers.subscription_complete` takes the pasted `code` and answers `waiting` until the person approves). The token goes straight into the person's own Mine Vault as an ai_subscription item and is never returned to the app, an agent, a log or an event. A person does this; an agent is refused. The API key stays as the alternative.
- Each provider's sign-in is in `host/src/seams/provider-signin.ts`: Claude by OAuth authorization code with PKCE (the one-year token `claude setup-token` makes), ChatGPT by device authorization (the file `codex login` writes), Grok by the Grok command line's own sign-in run in a private home that is deleted afterwards. The addresses are constants and every answer is checked, so a changed provider shows as a failed sign-in with words. They are unverified against live accounts until a real one runs them. The engine fills Claude's token into the CLI as before; Codex and Grok keep their sign-in files in the item, and placing them in the sandbox is still the engine's open step.
