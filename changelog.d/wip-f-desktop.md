- Fixed: an old agent desktop that nobody used stayed awake for ever. The check that puts quiet desktops to sleep now runs every minute, so an unused desktop sleeps after its idle time and then moves to the agent's workspace and browser.
- Nothing offers to make a new desktop computer for an agent any more. "Give It a Computer" is gone from the agent menu, About, Console > Computers and the New agent page; "Open Its Computer" takes you to the agent's Computer tab, where its terminal and browser are. Desktops that already exist can still be woken, put to sleep, watched and removed.
- An agent that asks for a computer is told what it already has: a terminal in its workspace and a browser in the Space browser, and the person's own Chrome only when they ask for it. Its instructions say the same.
- When an agent calls a screen or desktop file tool and has no desktop, the answer names the tool that works. When a Space has no browser for agents, the answer says so and says what gives it one (Docker on the Space's computer, or a server with Docker added in Console > Computers).
- Fixed: an old desktop whose Chrome sign-ins could not be read was recorded as moved with nothing lost. It is now marked as moved without its sign-ins, with the reason, so the agent signs in again once.
- Fixed: an agent's first browser call after an update could start a fresh browser profile and the later move of its old sign-ins wiped it. An agent whose old desktop has not moved now keeps using that desktop for the browser, and a sleeping desktop moves at the agent's first browser call.
- An agent that still has an older desktop shows a row "Older desktop" at the end of its Computer tab. It opens that desktop's live view, where you can wake it, take over and give it back.
- The plan an agent shows before it creates another agent no longer lists "Give it a computer".
- A move of an old desktop's sign-ins waits, without giving up, while the agent's browser is busy or someone has its controls.
- Console > Computers says in one line, on each old desktop's row, how its move to the agent's workspace and Space browser ended, and when to remove the desktop.
- Where an agent's terminal and browser cannot run yet, the Computer tab says what would let this Space run them and, for owners and admins, opens Console > Computers.
- After an update the server also removes old server images that no kept release uses, not only the agent, workspace and browser ones.
- A move of an old desktop's sign-ins never overwrites a browser that already holds sign-ins, never starts or copies a desktop that woke meanwhile, waits instead of failing when the Space browser or Docker is not there, and keeps trying once a day after a real failure.
- A desktop that has moved tells an agent's screen and file calls what to use now. The create-agent instructions, the agent Settings row and the Computer tool description no longer talk about asking for a computer, and outside agents have no "Open Its Computer" item.
- An old desktop's sign-ins are never copied over a browser whose state cannot be checked.
- Moving an old desktop's sign-ins copies only cookies, saved logins, site storage and settings (never Chrome's caches), checks the Space browser is ready before reading anything, waits longer between tries when the server cannot take it yet, and finishes the import even if the server restarted in the middle.
- Putting an older desktop to sleep now closes its Chrome cleanly first, so a sign-in made seconds before is kept.
- Moving an old desktop's sign-ins was proven end to end on real Docker with both real images: a cookie, a page storage value and an IndexedDB record made on the old desktop are read back by the page in the agent's Space browser.
