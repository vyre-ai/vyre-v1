- The server update backup is now consistent while the daemon writes: each SQLite database is copied with VACUUM INTO and checked, the other files are copied, and only the copy is tarred. A file that changes during the copy no longer fails the update.
- A failed backup now starts the server again instead of leaving it stopped. `vyre-server backup` takes the update lock and uses the same path as the scheduled update.
- An update that is killed or cut off now goes back to the previous release (at once on a signal, at the next command after a crash), and compose.env is rewritten whole instead of with sed.
- A lock left by a dead update process is reclaimed.
- `vyre run --env` works without a separate filler process: when VYRE_FILLER_SOCKET is not set it asks the server for each value as the caller (a person at View level), and scrubs those values from the command's output. With the socket set it reads from the socket as before.
- Two items in one folder with the same field name no longer break `vyre run --env`: the first keeps the plain name, a later one gets its item name in front (Stripe_live__api_key). If that name is taken too, the call is refused and names both items.
- `members.sso.set` now checks that the caller can use the Vault item that holds the client secret (vault.use), as connections and mail do. The item must exist in the Vault first, as the Console already does.
- `vyre-server backup` and the daily backup no longer stop the server: every database is taken as one consistent snapshot while the daemon keeps writing. Only an update stops the server for its backup.
- An update backup now also stops any container outside compose that still has the data folder mounted (named in the output), and starts it again afterwards.
- New `vyre-server restore FILE [--yes]`: it checks the file (readable, only space/ and caddy/, no links, every database passes integrity_check) before touching anything, asks for confirmation, backs up the current data, stops, restores, starts and checks health, and puts the old data back if the server is not healthy.
- `vyre run --env` never prints a fetched value, also not inside an error message from the server or a failed launch; each value fetched is a Vault use with the person as the actor.
- Vault search finds an item by name, handle, kind, field name or folder name, across Mine, Shared with me and the Space (never by a value).
