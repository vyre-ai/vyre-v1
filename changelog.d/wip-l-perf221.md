- Server no longer stalls on the calendar pull and the hook pump (rc.22 perf): Google pulls are incremental (updatedMin, full window every 6 hours), events are found by an index on calendar and provider id, an unchanged event skips the meetings call, pulls and the hook pump yield to the event loop, and the daemon warns any block over 200 ms and reports event-loop lag in the machines report.
- Calendar: the event pane says "This event is not there any more" only when the read says the event does not exist; a read that failed another way (server busy, dropped link) is tried again. Provider all-day events (dates kept as midnight UTC) are drawn on their own date in the viewer's zone instead of across two days, and the pane reads their date the same way.
- Calendar: a meeting that sits in several people's calendars (each attendee's copy has the provider's same event id) is listed once in a week: the copy on the viewer's own calendar, else the first one they can open.
- Calendar: the week and day view open one hour above the current time when today is in view, instead of at midnight when an early event is in the week.
- Calendar: with no calendar named, list_events and list_calendars cover the viewer's own calendars and the ones explicitly shared with them (direct, group or folder grant). An admin's role access to every member's calendar is no longer mixed into their own week or sidebar; opening another person's calendar by id still works.
