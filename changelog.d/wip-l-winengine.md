- A long data folder no longer breaks a chat on a CLI account. On Windows the turn died at once with "the MCP socket path is too long for a unix socket: 116 characters". The engine's MCP bridge now listens on a named pipe on Windows. On a Mac or Linux it uses a short private link when the folder path is too long, and the network wall does the same when the temp folder path is long. A test covers a 120-character data folder on Linux and on a Windows runner.
- A CLI account (Claude Code, Codex, Grok) on a computer that cannot sandbox it is no longer offered for turns. That covers Windows today and Linux without bubblewrap. Another of your accounts answers, and the chat says so in one line: "Claude cannot run safely on this computer yet, so Anthropic answered." With no other account, the reply says "This engine cannot run safely on this computer yet." and offers "Use an API key". It refuses before anything is downloaded or started. The account's page shows "Needs a sandbox Vyre cannot set up on this computer yet. Use an API key for now." in place of "Working".
- A failed reply says what happened for every code a turn can fail with, for example "Your AI account needs you to sign in again.", "This chat is too long for the model." or "The engine could not reach Vyre's tools.". "That reply did not finish." is left only for an error with no code. A test reads every code from the code that raises it, so a new code without words fails the build.
- Vyre can install Claude Code 2.1.316, Codex 0.166.0 and Grok 1.0.70 on Windows (x64 and arm64), as claude.exe, codex.exe and grok.exe, checked against the vendors' published sizes and SHA-256 sums (Grok's taken from the files). These installs start once Windows has a sandbox.
