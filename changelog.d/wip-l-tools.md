## What's new
- Agents find tools with far fewer searches. Every turn now carries a one-page capability map (about 1k tokens, in the stable rules section) that names the tools each area starts with. A chat opened on a thing lists that thing's core tools at once (a goal chat the goal tools, an Ask about a file the file reads, an Inbox chat the mail reads, a Vault chat the vault reads). A list result says which tool reads one item and lists it. An agent's ten most used tools (used twice or more) are listed at the start of its next turn.
- scripts/tool-discovery/measure.ts replays 29 tasks across Inbox, Calendar, Records, Files, Tasks, Goals, Projects, Vault, Chrome and crews through the real tool session with a scripted model and prints model calls, input tokens, searches and modelled wall time per task. FEATURES=map,place,learned switches the features on.
- Parallel tool calls. When a step asks for several tools, the engine runs the independent reads together (six at most at a time, one failing does not stop the others) and everything else one at a time and in order after them; a call the Gate may hold runs alone and still parks the turn. Results go back in the order asked. Every turn's stable rules now say "when steps do not depend on each other, call their tools together in one step"; the Anthropic request allows parallel tool use and the OpenAI, OpenRouter, xAI and OpenCode Go requests send parallel_tool_calls. A local or custom server, whose model may not emit several calls, gets tool_batch: up to six independent reads in one call, answered keyed by request id.
- The activity line (and the working island) reads "Reading 3 things" with the calls named when several tools run at once.
