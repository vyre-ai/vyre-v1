- Claude Code, Codex and Grok run on Windows, inside the same sandbox as on a Linux server. When WSL2 is on, Vyre imports a small pinned Linux of its own (Alpine 3.22.7, checked against its SHA-256) and installs the engines' Linux builds in it. Each engine runs there under bubblewrap: it sees only its work folder and its own home. Its only way out is the network wall, under the same egress policy as the Linux wall. It reaches Vyre's tools over the agent's own stdin and stdout, so no port is opened, and every connection still starts with its session's token.
- The first CLI reply after a restart shows "Starting the Windows sandbox, first turn after a restart" while the sandbox starts. The one-time set-up shows "Setting up the Windows sandbox, once: this takes a few minutes". A start that does not come up ends in plain words ("The Windows sandbox did not start.") and never hangs.
- With WSL off, a CLI reply says "Claude Code, Codex and Grok need WSL on Windows." and offers "Turn on WSL (needs admin and a restart)" with the exact steps, and "Use an API key". The account's page says what it needs.
