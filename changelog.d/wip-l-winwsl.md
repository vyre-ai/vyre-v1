- A Windows computer set to Contained runs Claude Code, Codex and Grok in the same sandbox as a Linux server. Contained is `VYRE_WINDOWS_SANDBOX=contained` until the computer's details have a switch, and Team Space turns are next. When WSL2 is on, Vyre imports a small pinned Linux of its own (Alpine 3.22.7, checked against its SHA-256) and installs the engines' Linux builds in it. Each engine runs there under bubblewrap as an unprivileged user: it sees only its work folder and its own home. Its only way out is the network wall, under the same egress policy as the Linux wall. It reaches Vyre's tools over the agent's own stdin and stdout, so no port is opened, and every connection still starts with its session's token. A Personal Space keeps Low integrity (RULINGS 14).
- In Contained mode, the first CLI reply after a restart shows "Starting the Windows sandbox, first turn after a restart". The one-time set-up shows "Setting up the Windows sandbox, once: this takes a few minutes". A start that does not come up ends in plain words and never hangs. With WSL off, the reply says "Claude Code, Codex and Grok need WSL on Windows." and offers "Turn on WSL (needs admin and a restart)" with the exact steps, and "Use an API key".
