Fixed: synced types no longer start their passes in one wave. A type's next poll sits at its own place inside the interval, the driver starts at most two passes a tick, and a poll whose connection already has a pass on its way looks again a few seconds later. A call that reaches the connection's calls-a-minute budget waits in line instead of being refused and asked again, and a pass reads each key from the Vault once instead of for every request. A stall over half a second now writes the stack of the code that held the loop (scheduler.loop_stalled).
