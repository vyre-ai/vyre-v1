- Exact recall: memory.quote and the new chat.history.search return the words people wrote in chat messages and in transcript rows (turns, tool calls and results, which is what a run step is), word for word, with who wrote them, when, and a link that opens the chat at that line. They search only what the asker could open themselves: a private chat they are in, a channel they are a member of. A person who was not in a chat never gets a line from it, not even through an agent that was. chat.transcript.search follows the same rule now.
- Recall for a message adds the top three matching quotes to the memory block, each with its source id (a message id or `<thread>#<n>`) and who said it; recalled facts carry their fact id so a model can close one with memory_forget. A memory link `...&m=<messageId>` opens the Chats place scrolled to that message and highlights it, paging back through older messages until it is held.
- The memory tools are the same for every model: memory_quote, memory_remember and memory_forget join memory_search in the default tool list (62 tools). API-key chats get them through the tool runner, Claude Code, Codex and OpenCode through Vyre's MCP server. Each agent's map is rendered into CLAUDE.md and AGENTS.md in its folder (rewritten when the nightly job rewrites MAP.md; a file Vyre did not write is left alone) and into the work folder a CLI engine starts in.
- Mac CLI engines: the Seatbelt profile now lets a process open `/` (macOS 26 aborted every sandboxed program at startup), the sandbox points HOME and TMPDIR at the person's scratch folder (Claude Code stopped with EPERM), the MCP socket binds through a short link when the data folder path is longer than a unix socket allows, and the sandbox roots follow the real path of the data folder.
- AI accounts per agent: an agent's settings hold a chat key, an ordered fallback list and a Memory key, picked from the person's own accounts and the shared Vault AI providers (agent.toml `vault.account_fallback` and `vault.memory_key`). The resolver follows the ordered list, then the Space backups; a turn whose account is refused or out of quota before it said anything is handed to the next account in that order and the one that served is metered. Space Settings (admins) and Personal Settings get the same picker under Memory and privacy, for Space, project and personal memory; memory.key.resolve answers which account pays for a scope, and no account means rule-based upkeep.
- memory.used shows what recall put in front of the agent for a message (facts and exact quotes, re-read under your access); the engine records the source ids per message with memory.recall.record, so the chat can say "Used N memories" and "What the agent knew here". Ids only are stored.
