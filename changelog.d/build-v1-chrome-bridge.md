- Vyre for Chrome now works against a running app: the daemon answers the extension's hello, Space list and switch, agents list and login check, and runs its nine vault capabilities (match, use, fill, save, update, folders, site rules, share) as the person who owns the Space, through the Space's own pipeline and grants. A vault fill is pushed to the page by the filler (a `browser` place), and says so when no extension is connected. A locked vault reads as `locked`. Saving a login no longer fails for want of an idempotency key.
- The person chooses which Space's agents may drive their Chrome (`/local/chrome/optin`, kept across restarts and announced to the extension), and an agent's Chrome tool call (`/local/chrome/tool`) reaches the person's own tab only for an opted-in Space and an agent the person can see.
- The bridge live test no longer asserts `not_available` for hello: it now proves find, fill, check and save end to end.
- Vyre for Chrome works on a Team Space for every member, not only the owner: the app hands the desktop's daemons the person's own signed-in session for each Team Space (`/local/chrome/spaces`, memory only), the Space list is the Spaces this computer is signed in to, and every call goes to the Space with that session so the person's own grants answer. A fill asks the Space to return the value to the person's own computer (the vault now allows that for a person at Use level into their own browser, never for an agent and never when the host's own browser place is that person's), which puts it in the field and passes nothing on.
