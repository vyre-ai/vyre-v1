Changing a sealed value that already exists now puts it into the Vault only after the record change is saved, so a refused change leaves the old value alone; if the Vault cannot take it, the change is undone and the answer says the value was not saved (the record's history then shows the change and its undo as two edits, and the version goes up by two). If the server stops between the save and that put, the record keeps the new date over the old value: stale, never empty.
