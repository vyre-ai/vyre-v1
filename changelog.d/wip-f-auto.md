- Building a connector: the one test read now refuses a private, loopback or cloud metadata address (also a name that resolves to one) before the Vault key is put on the request.
- Building a connector: a test read that fails now says why in one line (the app refused the key, nothing at that address, the app did not answer, the app had a problem, or the Vault did not give the key), with what to check next.
- Automations no longer offers to set up an AI account's own key as a connector, and a Vault item that is an AI account's key no longer shows Add to Automations. An offer for an item that was deleted or that you cannot see is no longer listed.
- A Run whose Vault item is gone now names the item in its error ("There is no Vault item #Acme that you can use"), so you know which key to bring back.
- An item named like "Notely API key" is offered and built as the app Notely, in Add to Automations, Sync to Records and the setup offer.
- Vault: the open item stays open when another item is used and the list re-sorts; before, the detail jumped to whichever item moved to the top.
- Automations: a web request trigger shows its address on the trigger card, with Copy, so you can paste it into the app that calls it without going to the Settings tab.
- Vault on a phone: the Automations buttons on an item (Sync to Records, Add to Automations) wrap under the heading instead of running past the edge.
- A Vault key goes only to a host a person approved for it. When an agent's test read would send a key anywhere else, it waits for you: Allow sends it once, Always allow keeps that host on the key, Deny tells the agent. The host of the key's own saved address needs no approval. Automations, `automations.key_hosts.*` lists, allows and removes approved hosts.
- The test read looks a host up once and connects to exactly the address it checked, so a name that changes its answer cannot move a key to a private address.
- An HTTP request step's key no longer follows a redirect to another site, whatever the key's header is called.
- A step that uses a Vault key can be added or changed only by someone who may use that key ("Step 2 uses a key you cannot use"); other steps stay editable. A key cannot go to an address whose host is filled in when the step runs.
- Used in, and the Move to Trash confirm, count the Automations you cannot open that use the key ("and 2 more you cannot open"), and the confirm says agents lose the key too.
- Vault: a key's page lists where it may be sent ("Sent to"), and a person who may use the key can remove a host with one press.
- A task step in a Space Automation no longer offers anyone's Assistant as the agent to hand work to; a Personal one offers only its owner's own.
- A held test read names the key the server resolved, with its name ("Scout wants to send #Notely (Notely API key) to api.notely.com"), and a read whose host or key cannot be named waits for a person instead of going out.
- Binding a Vault key to a connector by an agent waits for a person when the connector's hosts are not approved for that key; the card names every host. A connector request carrying a key goes only to hosts approved for it, and says which key and host when it is refused.
- A key's own saved address approves its exact host only, not other sites under the same domain.
