- Everyone now has a private Personal calendar from the day they join (the owner from the start), so you can add an event without connecting Google or Microsoft first. People who joined earlier get theirs the next time the server starts.
- The Console's Infrastructure page now shows the server's memory and total disk size (it said Unavailable because nothing reported them); the server updates them every minute.
- Synced record types (from a CRM or other outside app) now refresh on their own at their set pace, even after a failed sync or a missed poll, wait longer after repeated failures, and skip paused or disconnected apps; they no longer depend on someone pressing Resync.
- Filling a document from a record, previewing an email as a record and checking an import against existing rows no longer fail with "Something in what you entered is not right"; a scheduled call and an agent's own calls to other parts of the app also carry their idempotency key.
- Setting an email's HTML (including from an agent) and restoring an earlier version of an email no longer fail with "Something went wrong on our side"; the same fix covers deleting a calendar, calling in or disconnecting a calendar account, staging files, site builds and previews, publishing a site, call hang-ups, voicemail and meeting cancellations, which each sent an event their listing did not declare.
- A Personal calendar you delete stays deleted, and the server no longer waits to make everyone's Personal calendar before it starts, so a large team's server is ready at once.
- Test only: a hung MCP call in the fake CLI now times out after 20 seconds, and the agent-gate golden flow says what the agent said when no hold appears.
- The Windows leg of the desktop build now proves the install end to end on a real Windows runner (silent install, install.ps1 against this build, the app starting and answering, a clean uninstall both ways) and runs on any change to the installer; `install.ps1 -Uninstall` now also runs the installer's own uninstaller.
- `vyre-server update` now backs up your data while the server keeps running and stops it only for the switch, so a team's Space is down for the restart (seconds) instead of the whole backup (minutes); `--stopped-backup` keeps the old order.
- A meeting that appears in several calendars (or on a call) is now settled once, by one rule (the first calendar copy's title, start and end), instead of being rewritten on every refresh; and saving a record with the values it already has no longer adds an entry to the history.
- A server install on a cloud machine with a plain disk now shows two real ways forward (the provider's encrypted volume, shown as your statement and never as verified, or an explicit and recorded choice to go without) instead of commands that need a spare disk; doctor and the Console say plainly when the data is not encrypted at rest.
- Installing with `--relay` no longer ends on a link that cannot be opened: the installer and `vyre-server claim-link` say what the relay is for, and how to get a web address (`--domain`); no public port is opened without a domain.
- Re-running the installer with `--domain` (or `--relay`) on an existing server now changes how it is reached, says so, and keeps the data. The installer adds Docker on Debian and Ubuntu as documented, checks its DNS names and says which one is wrong, `--uninstall --purge` explains how to confirm from a pipe, `vyre-server logs` says it is following (and has `--no-follow`), and a backup on the same disk as the data says it is no protection and how to copy it out.
- Backups are written next to the data (so a data folder on an encrypted volume holds them too), a backup refuses to run when the data folder holds no Space, and `vyre-server update` closes a relay server's public ports 80 and 443.
- `vyre-server doctor` and the Console now also say where agent browser sign-ins sit: on Docker's disk, and whether that disk is encrypted; a server whose domain was set in the Console keeps its ports open through an update, and restoring a backup into an empty data folder now works. A provider's encryption and a plain-disk choice each show their own next step.
