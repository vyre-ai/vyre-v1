A connector defined in one call can now carry a JSON or form body, leave out a query key, header or body key when an optional {input.x?} has no value, page its lists (page, cursor, offset or link) and name a health action, and sign in with HTTP Basic or a header template over several secrets. connectors.init no longer asks for an idempotency key.
A connection that holds a key always has a host record, empty until a person allows a host, so an agent that publishes a connector with a new address cannot make the key travel there, before or after a restart. Older connections are recorded once from the connector version live when they were made. A tenant domain is recorded with its port. A connector definition refuses more framing headers and any action header that is the sign-in, and the safety-flag check matches exact names. The approval card names a domain pattern in plain words and records the allowed hosts on the connection.
The connect card pins the service version it showed: Connect is refused, and no key is tried, when the service was republished after the card opened.
The connect card pins the connector's server-side revision (not the version text) and the key and connection are made only if it still matches.
The connect card pins a revision the server counts on every change to a connector (a roll back too), and takes back a key it stored when the service changed while connecting.
