- Your own Claude, ChatGPT or Grok sign-in now answers your own chats on a Team Space server with nothing else to turn on. "Let the Space run work on my subscription" now only decides whether automations and other people's work may use it (owner ruling, 3 Nov).
- A Space can have several Space AI accounts (owner ruling 9). An owner or admin sets what each shared key pays for: team chats (everyone or some groups, and only for people with no account of their own), automations, goals and wake-ups, or agent work (all agents or some). Each account can also have a monthly spend cap. Your own chats run on your own account. Every other turn runs on the cheapest Space account that covers that kind of turn, serves its model and is not capped. A key pinned on a chat, an agent or an automation step still wins, and when it cannot pay, the turn says why. When no account serves a team chat's model, the chat runs on the team account's default model and says so in one line ("Ran on GLM 5.3; Claude isn't on the team key"). It fails only when you pinned that account and that model together. The Space AI key you already have becomes a Space account with every use on, so nothing that runs on it today stops. A key shared with the Space before this keeps paying for the people who can use it. Caps count the cost each turn records, which is 0 until real per-turn prices land (lane l-turninfo).
- A Space connection's key, an app hub's key and a Space skill's key now each go in their own Vault folder (Connections or Skills), shared with everyone in the Space, so every member's agent can use them. Before, they went in the first shared folder, or in a new folder shared with nobody. When a folder cannot be shared, Vyre now says so instead of keeping the key private without telling you.
- Before you send, a chat now tells you when you have no AI account that could reply there: "No AI account for this chat yet." with Connect yours beside it, which opens the connect sheet in place. An owner or admin can also set a Space AI key from the same line. Console Overview now shows "Your team has no AI account" when a Team Space has no shared AI account.
- After a Team Space server restarts or deploys, your own AI accounts keep working with nothing to type. If you signed in with Google, Microsoft or GitHub, the server reopens your key from its sealed copy, and each reopen is an audit row. If you signed in with your password, the app gives back the key it kept in memory as soon as it reconnects. The in-place password prompt on Space servers is gone. If a reloaded browser tab no longer has your key, sign in again on that device.
- Company keys now protect themselves. A Google delegation key, the Microsoft app's secret or a sign-in app's secret always goes in the Restricted "Company connections" folder, whichever shared folder it was put in, and also when the owner's agent stores it during setup. Members with Edit on the named folder cannot reveal it, and only an owner or admin can add one.
- Closed an insider hole. Connecting a mailbox, making a connection, or giving a connection a secret now checks that you can use the Vault key you name, before anything is saved. Before, anyone could point the server at someone else's key, such as a shared Stripe key, and have it sent to a mail server they run.
