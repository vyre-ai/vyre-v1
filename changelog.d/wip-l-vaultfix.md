- A Space connection's key, an app hub's key and a Space skill's key now each go in their own Vault folder (Connections or Skills), shared with everyone in the Space, so every member's agent can use them. Before, they went in the first shared folder, or in a new folder shared with nobody. When a folder cannot be shared, Vyre now says so instead of keeping the key private without telling you.
- Before you send, a chat now tells you when you have no AI account that could reply there: "No AI account for this chat yet." with Connect yours beside it, which opens the connect sheet in place. An owner or admin can also set a Space AI key from the same line. Console Overview now shows "Your team has no AI account" when a Team Space has no shared AI account.
- After a Team Space server restarts or deploys, your own AI accounts keep working with nothing to type. If you signed in with Google, Microsoft or GitHub, the server reopens your key from its sealed copy, and each reopen is an audit row. If you signed in with your password, the app gives back the key it kept in memory as soon as it reconnects. The in-place password prompt on Space servers is gone. If a reloaded browser tab no longer has your key, sign in again on that device.
- Company keys now protect themselves. A Google delegation key, the Microsoft app's secret or a sign-in app's secret always goes in the Restricted "Company connections" folder, whichever shared folder it was put in, and also when the owner's agent stores it during setup. Members with Edit on the named folder cannot reveal it, and only an owner or admin can add one.
