A Vault key now has a clear path to an Automation step. A key, env block or login shows Add to Automations in the Vault. It starts a chat with your assistant on your own AI account, with the app name, the Vault handle (never the value) and the new connector-builder skill. The agent finds the app's API docs, drafts actions and triggers through the live connector API, runs one safe test read, shows a review card and waits for you to publish. A published connector then shows in the step picker under Your connectors, one step per action, already pointing at its connection. Under the button the Vault lists the Automations that use the key, and each opens. In the HTTP step, a key picked from the Vault also names the other steps that use it. The Automations start page offers Set up for a newly saved key, and offers are made only for keys, env blocks, logins and loose items. If there is no AI account, the account needs signing in, the Vault is unreachable or you can only view the item, a short notice with a fix button replaces the error. New capability: automations.vault_usage (generated files need regenerating).

The step picker is now a real picker: a search field, app logos on every row, the groups Vyre, Your connectors, Connected apps and AI and code (with Code, Wait, Paths and Loop in their groups), and a Build a connector row at the end that starts the assistant on a new connector. Step cards wear the app's logo too. The shared Menu takes a search field, a leading element per row, a fixed width and pinned rows. Vault items for known apps show the app's own logo, including GoHighLevel, from the icon files that ship with the app, instead of a letter tile. A connection now lists the Vault handles it uses, and a Vault item counts the Automations whose connector steps run on it. A setup offer for a Mine item is shown only to the person who saved it. Two Automations tests that ended early on a warm run now keep the event loop alive while they wait.

The connector builder now takes charge. A chat started by Add to Automations (or the picker's Build a connector row) loads the connector-builder skill as its focus on its own, and in any other chat the skill is in the skills list for requests like "hook up Resend to Automations". The agent reads the app's API docs itself (new automations.read_docs, read only, public https, plain text and links), offers a short tappable choice of actions, builds the draft in one call (new connectors.define), tests every chosen read with the key header the docs name and shows the results as a compact card (new automations.connector_card), asks before publishing, binds the connector to the Vault item and says where it now shows. Read tests report the status the app answered. An agent cannot mark a write as safe to test. scripts/e2e/connector-builder.e2e.ts runs the whole flow for real against a booted daemon and the real Claude CLI; it is not part of CI.
