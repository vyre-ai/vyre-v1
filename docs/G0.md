# G0: the gate before the build window

`node scripts/g0-check.ts` prints one line per condition and exits 0 only when all are true. CI proves the script with `scripts/g0-check.test.ts`; the lead runs it for real (it needs the tracker and `gh`).

    node scripts/g0-check.ts [--root DIR] [--packets-json FILE] [--skip-remote]

`--skip-remote` leaves out the tracker and `gh` (offline or CI use); the packet, main-green and budget lines then fail, so it can never report G0 ready.

## What it checks

| Line | Condition | How |
|---|---|---|
| F1 | manifest types and generator | `manifest/`, `generated/hash.txt`, `npm run gen -- --check` exits 0 |
| F2 | contracts | `contracts/` present, no TODO in non-test sources |
| F3 | kernel | `kernel/` and the contract freeze tests present; suites are proven by the main run |
| F4 | 72 modules, each with owner and status | `host/modules.json` count, `scripts/lanes-check.ts` exits 0 |
| F5 | host | `host/src/` present; the echo test is proven by the main run |
| F6 | testkit and seeds | `testkit/`, `fixtures/seed/` |
| F7 | spikes | `spikes/REPORT.md` names S0 to S6 and S12 |
| F8 | sync protocol | `sync/src/protocol.ts` |
| F9 | UI skeleton | at least 20 `ui/src/<Component>/props.ts` files |
| F10 | CI skeleton | ci-select, ci-budget, workflows test, and `docs/ci/skeleton-run.md` shows a no-op execution under 90 s (ruling 12: execution, not queue) |
| F11 | manifests | `manifests/` and `generated/registry.json` |
| F12 | 0.6 import | `scripts/import-0.6.ts` and `docs/import-log/` |
| F13 | lane briefs | every lane in `scripts/lanes.json` has `docs/lanes/<lane>.md` |
| F14 | accounts | `fixtures/ACCOUNTS.md`; waived while P-PR_64 is open (see below) |
| F15 | repo, protection, prewarm | last run on main is success |
| packets | prep packets | every prep packet in the tracker is done except P-PR_47b, P-PR_64 and P-PR_75 itself |
| contract-hash | contract frozen (ruling 9) | `generated/hash.txt` is a sha256 and the `contracts/tests/frozen-*.test.ts` files exist |
| main-green | main is green | `gh run list --branch main` latest conclusion |
| budgets | budgets met | budget job of that run succeeded and the no-op run is under 90 s |
| dry-run | hour-1 dry run recorded | `docs/dry-run-hour1.md` has the median lead review time and the CI push wall time |

## Waivers

- P-PR_47b (real phones, ruling 3) and P-PR_64 (test accounts the owner supplies) do not gate G0. F14 prints as `waiv` until `fixtures/ACCOUNTS.md` exists.

## Owner forks (ARCHITECTURE-V1.md section 14, both ruled)

- F-A, passkey sign-in: out of v1. Sign-in ships password, optional TOTP and GitHub. Vault passkeys and extension WebAuthn interception are out. A `passkey` second-factor kind is declared in the manifest as `deferred`, so adding it later is an addition, not an edit.
- F-B, Apple-dependent artifacts: nothing depends on Apple. The Mac desktop shell ships ad-hoc, the iOS build is a sideload build, the phone default is the responsive web app, and the keychain is never required (ARCHITECTURE-V1.md 10.7). If the owner activates an Apple membership, TestFlight and notarization are added as separate stages and never block the tag budget.
