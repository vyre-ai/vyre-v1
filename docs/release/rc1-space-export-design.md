# Shared Space export: implemented privacy boundary

The approved initial scope is **shared Space data**. This is not a backup image and does not claim requester-private chats or Personal files. V1-SPEC line 34 requires the owner ZIP and excludes secret values, others' private chats and personal memory; line 122 requires sealed fields masked in exports; line 208 defines provider-native export snapshots; lines 290–294 define retained file versions. Full binding-scope acceptance remains subject to independent release review.

| Category | Canonical source and inclusion |
| --- | --- |
| Profile | spaces.get for this Space under the original authenticated owner. |
| Schema and records | schema.describe plus paginated records.query. Legitimate system types remain eligible. Space scope and actual resource ancestry must prove shared ownership; private parentless resources stay excluded even when a broad Owner grant allows reading them. Unknown scope fails. Current rows, versions and fields reconcile on a second pass; deleted rows stay absent. Sealed values become explicit masks. |
| Files | All root-page files plus recursive scope=space folders. files.versions supplies every retained version; files.read supplies authenticated chunks. Preserve exact bytes/hashes. Resolve the current pointer by canonical current bytes and hash, including conflict versions with equal version numbers. Missing required provider-native snapshot bytes fail the export. |
| Chats | Public channels and verified channel/thread descendants only. threads.get independently confirms each candidate; private/invite channel links, private/group roots, Ask/helper/Console kinds cannot inherit a public parent. Canonically authorized shared encrypted envelopes remain unchanged; unsafe preservation fails explicitly. |
| Settings | settings.list(scope=space); no person overrides, Vault or account/session reads. |
| Manifest | Exact paths, sizes, SHA-256 hashes, source head, mutation revisions, IDs/versions, current file pointers, exclusions and credential-value omission metadata. No successful archive may omit a manifest-declared entry. |

The collector uses ctx.call, which retains the original principal, Space and trace. It never uses system(), an arbitrary principal, raw databases or unrestricted blob enumeration. Resource ancestry supplements canonical permissions so broad Owner reads do not convert private content into shared content. Personal Files, private/group chats, private helpers, personal memory, Vault values and local session imports are outside this shared scope.

Credential-bearing file versions are omitted with explicit manifest reasons; bytes are never silently rewritten. Credential-bearing record/setting values are omitted with exact metadata pointers. Sealed fields are masked. Final legacy packaging may not silently drop collected entries: an unexpected prohibited entry fails the whole export.

Consistency checks include canonical ID/version and file metadata/history reconciliation, the durable source head, and a revision incremented before and after public content/access mutations enter their handlers. Active relevant writes block collection and persistence, including writes that began before the snapshot baseline. The revision guard continues through encrypted persistence and resource registration, closing the interval before a concurrent mutation's log commit. Required read errors, missing bytes, repeated cursors, unsafe paths, cycles, inconsistent current file pointers, unknown record sharing or concurrent mutations fail explicitly. Canonical Files root initialization finishes before the snapshot boundary.

Bounds: 240 MiB of collected contents, 256 MiB persisted ZIP, 100,000 canonical operations, with a cumulative 100,000 retained-item limit across paginated categories, roots and descendants and 120 seconds, with bounded pages and 128 KiB source file chunks. Existing private archive reads use authenticated chunks of at most1 MiB. Only the current active person owner with server.backups and records.export can collect, poll or read; authority and expiry are rechecked after blob retrieval. Ready metadata appears only after byte-for-byte verification and completed resource registration. Failure removes ciphertext and pointers. Retention is 24 hours with boot, minute and access cleanup; ownership transfer/restart invalidates prior requesters.

The current contact matches its canonical updated version; a deleted contact is absent. Both retained shared file versions match exact bytes and hashes. The current pointer matches canonical bytes. Every manifest entry exists with its declared size and SHA-256 hash. One credential-bearing file version/current pointer is excluded explicitly. Actual broad Owner reads can see private agent/envelope rows and a contradictory invite child/helper under a public parent, yet none enter the archive. Another person's Personal file/private chat, private helper, personal-memory fact and a Vault item/value stay absent.

HTTP negative fixture: missing provider-native snapshot bytes returns 422 and persists no additional archive. Unit coverage also rejects required read failures, record drift, changed source heads, mutation-start revisions, unsafe private descendants and post-collection prohibited entries; preserves a shared encrypted envelope exactly; and proves credential values omitted with metadata. Paused-blob tests cover owner/permission/expiry changes during read/status and persistence cleanup failures. Actual transfer tests prove resource owner and old/new roles, restart persistence and requester denial.

A production Console export from the verified Console slice is reused against this lane's actual backend, with real browser ZIP download and required manifest/schema/files/chats/settings entries asserted.
