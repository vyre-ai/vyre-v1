# Lead decisions for the v1 architecture (binding inputs for ARCHITECTURE-V1.md)

Scope override: the 23 Oct DESIGN.md "defer" list is superseded by the owner's 24 Oct full scope and V1-SPEC.md. Agent computers, Chrome, Sites, mail, calendar, Google/Microsoft/GitHub, mounts, Inbox, console, mobile are ALL v1. Only Forms and Campaigns may land after the 12-hour window (they build on primitives). Voice and Mac/Windows desktop control stay out.

1. Repository: a fresh lean monorepo for v1 (new repo, e.g. vyre-ai/vyre-v1, or a clean `v1` root in vyre-ai/vyre; architecture picks one with reasons). Copy KEEP code from 0.6 (kernel core/gateway/store/grants/seal/audit/door/contracts/conformance/modules/flows/golden, core/gate, lib/one-yes, relay client+node, module-sdk, core/mcp, harness/mcp, modules/hands-chrome, signing/release scripts) as starting files, then CLEAN. No guard machinery copied unless listed as kept. History not carried.
2. Runtime: Node 24 only, TypeScript via type stripping, node:sqlite (no native optional deps). One Space per server, one daemon `vyred`.
3. Contracts first: every capability, event, record schema, agent tool and extension point declared in one typed manifest format (extend kernel/contracts + module-sdk). Generated from manifests: server routes, typed client, MCP tools, docs, test skeletons, permission catalogue rows, event catalogue.
4. Data: kernel event log is the source of truth; projections in SQLite per Space; sync = custom server-authoritative op-log on that log (research-sync.md), Yjs for long text; device replica SQLite (expo-sqlite native, wa-sqlite + OPFS web) encrypted (SQLCipher or app-layer); E2E rows as ciphertext.
5. Permissions: kernel grants + the CONSOLE-SPEC evaluation (role, grant, clearance, policy; agent intersection); one `authorize` in the gateway used by API, sync filter, search, MCP.
6. Agent runtime: REWRITE the turn engine as queue-per-thread over the event log; drivers: API providers (Anthropic, OpenAI, OpenRouter, Google, xAI) and CLI engines (Claude Code, Codex, Grok) in per-person sandboxes; warm engine pool for speed; lead/listen modes; plan mode; background waits as Runs.
7. Client: one Expo/RN codebase (web, iOS, Android; desktop = thin shell around web). Every place is a Kit view over the typed client; shared component library (tabs/strip/pane, ask, composer, recipients, menu with Report a problem, row) mirrors the prototype's VyreUI.
8. Diagnose: trace id end to end (device to server to providers), structured JSON logs into a logs table with retention, health checks per manifest, doctor, support bundle to reports.vyre.run, replay sandbox.
9. Speed budgets in V1-SPEC.md are acceptance tests (perf checks in the fast lane).
10. CI: <15 workflows; affected-only on the self-hosted fleet for every push (ci-select reused), Node 24 only, heavy-env tests tagged and pre-provisioned, per-file pass cache by import hash; full suite only on tags/release.
11. Comms: Gmail and Microsoft Graph APIs (DWD / admin consent) for mailboxes, Resend/Mailgun for Space sending and inbound routes, Twilio for SMS/voice.
12. Compute: Docker for agent computers (Chrome + VNC/stream, Vyre for Chrome) and Sites (Caddy in front, ACME via lib/acme), Documenso container for e-sign.
13. CI time budgets (binding, owner 24 Oct): per push affected-only checks 1 to 5 min; merge to main (whole fast suite + golden flows on the seeded Space + perf budgets) under 10 min; a release, from tag to live (full suite, build server image, web, desktop shell, Android and iOS in parallel, sign, deploy server and web, update channel) under 25 min. Enforced: any test file over 20 s fails CI unless it is in a short named "slow" list that runs only in parallel slots; suite sharded across the 24 runners with prewarmed caches and pass cache by import hash; mobile store builds run in parallel and never block server/web going live.
