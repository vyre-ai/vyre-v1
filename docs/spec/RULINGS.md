- 62 (amended) | A member's own AI account on a Space server | Owner ruling, 3 Nov 2026 ("its fine to put it encrypted on the server in their own folder ... make it seamless"). Ruling 62 said a Space server holds the key of its owner alone, so no member of a server Space could use their own Claude, ChatGPT or Grok. Now a Space server may hold any person's key in memory while a signed-in session of that person's that handed it over is live: signing in with a password hands it over (POST /vault/key/unlock on the Space's address, https only, never the admin token), sign-out or the end of their sessions drops it. Unchanged: the key opens that person's Mine items for their own turns only, never another person's or an agent's for someone else; it is never written to disk unwrapped, never readable through any API, and its use is logged. When the server does not hold it, the member's turn runs on the Space AI key and the chat says so. Their own computer's daemon still takes it as before. To follow (approved by the lead, same day): a wrap of the key that the server opens after a Google or GitHub sign-in, so a member who never types their password is not asked for it. Its two risks, accepted by the owner: (1) the wrap's key lives on the server, so whoever holds the server's disk and that key (the Space's operator, a backup, a stolen machine image) can open every such member's Mine items at any time, signed in or not; (2) whoever controls a member's Google or GitHub identity (for example a Workspace admin who resets that account) can open that member's Mine, including their personal AI sign-ins, not only the Space's data. Mitigations: the wrap is made only while the key is held from a password unlock; its key is a random server secret beside the vault master key, never in the database; it opens only inside the SSO and GitHub sign-in after the provider's proof and binds to the new session; every open is an audit row (who, when, which provider); reset and password change drop it; Vault has "Forget on this server"; an owner can turn it off in Console (Space security), which drops every wrap.
